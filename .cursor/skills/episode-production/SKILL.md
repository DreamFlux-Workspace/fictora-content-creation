# Episode production

You are the agent. The human is the gate. The desk folder is the review surface.

**Repo:** `fictora-content-creation` only. **API:** deployed Drama Generation `/v1/*`. **Tools:** `uv run fictora-produce` (the stages) and `uv run fictora-ops` (desk, ledger, notes). `--help` on any command is the truth for its flags.

## Two rules

1. **A human says yes before money moves.** The look (once you drew a look frame), plates, voices, the script and its pitch card, board, the spend yes. One gate per yes. No batched gates. Silence is not consent; a yes from last time does not carry forward.
2. **Render once.** Every paid unit is rendered once. A second render needs a written cause naming what in the direction produced the fault. "Try again" is not a cause.

## Desks created before 6 Oct 2026 keep their original behaviour

New rules apply to new desks (user decision, 6 Oct 2026, "only for new desks"). Fixes that change no voice, character or look also reach every desk (founder, 7 Oct 2026): `join` lays a steady sound bed under a loud seam on a desk created before 6 Oct 2026 too (the bed only: it never trims a silent head there, since a trim cuts picture). Exceptions that only stop a second charge apply to every desk (founder, 7 Oct 2026): a re-run after a lost reply sends the same request (the server hands back the job it already has), and a dropped connection while `step` waits never marks the desk failed (run the same command again). A desk created before 6 Oct 2026 (local date) produces exactly what it produced before, bug and safety fixes included: its face detectors are the older ones; it never draws system panels; its captions keep the line-window spreading, the wording it always had, their dashes, and `house` (Subtle) when no style is set, and it is never asked for the caption preview. Everything else on this page is for new desks.

- How a desk is placed: `rules_epoch` in `production.config.json` (`start` stamps `"2026-10-06"` on every new desk), else `series.json` `day`, else the folder's date prefix (`2026-09-26-…`). No date at all: the current rules.
- `uv run fictora-produce rules-epoch --desk D` prints the desk's epoch and why (free). Only on the human's say-so: `--set 2026-10-06` opts an older desk in to the current rules; `--set legacy` keeps a desk on its original behaviour.
- `uv run fictora-produce continuing-fixes --desk D [--from-episode N]` (free, dry run) records the Group B marker for a desk created before 6 Oct 2026, from its next unstarted episode on, in step with the server. The kit has no Group B fix left: per-word caption timing and captions without dashes reach every episode of every desk without it (founder, 9 Oct 2026). The pitch card is the server's and holds every desk from its next episode (decision A, 21 Oct 2026). A board behind a script edit is a server warning and films (founder 8 Oct 2026). Pass the server spine's `continuing_fixes_from_episode` as `--from-episode` to stay in step (the later wins). `--apply` writes it, only on the founder's sign-off. Earlier episodes keep their original behaviour. Never use `rules-epoch --set` for this.
- The legacy code paths are frozen for those desks: never change them.

## Never

- Chain two stages in one turn, or run two `step` calls in one turn unless the human asked to catch up.
- Approve plates, script or a board in the turn you enrolled them.
- Overwrite a desk file. New version, new `-vN` name (`fictora-ops next-path`). A desk that already exists for that date and slug is refused by `start`: never delete it or pick another folder to get round it; ask the human.
- Write your own HTTP around the API. Where no command exists it is a DEVIATION (reference.md) and a backlog line.
- Download a media URL (a take's stem or track, music, a take, a board) with Python `urllib` or a script of your own: the media host refuses urllib's default client with 403 (Cloudflare "error code: 1010", L-20261014-21). Every kit command already saves what it needs; for any other file use `uv run fictora-ops fetch URL --out PATH` (a new file; `fictora-ops next-path` names one). It sends a browser user agent and tries again after a refusal, so `curl -A` is never needed.
- Fetch, save, print or quote a compiled prompt (`GET /v1/jobs/{id}/provider-spec`). Record job ids instead (Prompt policy).
- Clone or read `fictora-drama`. Edit product code or settings to get a different look.
- Print or commit `FICTORA_DRAMA_GENERATION_SERVICE_TOKEN`.
- Retry a video job stuck in post. `cancel-job` it.
- Call `POST /v1/video-generations/{id}/post-production-runs` (hosted post is off). Do not use `--no-api-captions` unless the human wants raw-only enrol (server captions are on by default).
- Regenerate the story or re-film every take to change a voice.
- Hand over a raw take. A take is not done until the local finish ran.
- Copy a desk folder to try something. A copy keeps the same `spine_id`, so it is the same server story: an edit, redraw or film on the copy changes the producer's real story. The kit stops such a command and names the other desk (`Stopped: this desk's story (spine …) is also the story of: …`); pass `--shared-spine-ok` only when the human says both desks are meant to share it. Reads and local post (`status`, `spine`, `review`, `join`, `trim`, `set-bed` …) are never stopped.

## Pitch card: the script, approved before any paid draw

The pitch card is the server's card of the written script (decision A, 21 Oct 2026; the app's Create flow shows the same card): each take's shots in plain words, the line apart from the scene, the face as a stage direction, where the episode opens and where it ends, and the world's rules folded below. It is read, never written: no model call, no spend. Approving it is the producer's yes to the episode before anything is drawn. The old desk card (`epNN/pitch-vN.json`, `pitch-approvals.json`, written before the draft) is no longer read or written; write the idea into the brief instead.

- Read it with the producer: `fictora-produce pitch --desk D --episode N`. Check every line and shot against the world's rules.
- A change they ask for: `pitch --desk D --episode N --change "..."` (recorded on the server), then `line`, `edit` or `rewrite`; the new draft needs its own yes.
- Their yes: `approve --desk D --gate pitch --episode N`.
- The server's own warnings on the script (faces, the premise device, world rules) print at the script gate with the other server warnings.
- Shouted lines and voices are the writer's call, not the card's.

Read the card with the producer against these:

- **PG through the aftermath.** Never a kiss, an embrace or touching lips (Fictora policy: never remove the frames' PG bans). The pair springing apart, lipstick smeared on his mouth, her thumb on her own lip, hands meeting on an umbrella handle.
- **One charged situation; romance in subtext; no invented prop business.** One throughline, not a plot turn every beat. No business the story did not ask for (a pole gripped, a lamp, pointing at a wall).
- **Pacing is the server's.** The server decides how many lines a take holds; a silent beat is fine. Never add, split or trim lines to hit a count of your own.
- **Every line checked against what the speaker sees and does** ("weren't you closed?" from someone already eating; a new bowl when she has one).
- **World rules written at episode 1 and checked** in every pitch, beat and board row ("Sota cannot feel or touch a ghost").
- **Faces fit the moment, not the genre.** Comic marks for a light, awkward or petty moment, even in a serious show; plain faces for dread, grief, danger or tenderness. The server warns on a comic face on a grave beat.
- **Write the real age** on every cast card. Digits are preferred; an age in words is read correctly by the server, so it is no longer a warning.
- **Hook line: show the server's pick** (decision B6, 21 Oct 2026). It is on by default (the writer's stakes or rule line); show the producer the words and the options (`hook-line --list`), and change it only on their word: `hook-line --pick K | --text "..." | --off`, or `finish --hook-line "..."` / `--no-hook-line`, which save the choice on the server first and burn the line the server answers. Print the server's notes on it word for word. Whether anyone shouts is the writer's call: do not ask.
- **About 10 syllables a beat** for Korean and Japanese lines (about 11 s of speech a take).

## Brief

Pick the nearest `--preset-id` at `start` (`fictora-produce presets` lists the published ids; `start` checks the id before it makes the desk and a wrong one names the valid ids), even for our own look (Cold Gate `modern-dark-fantasy` is the closest to horror; the Dead Light horror preset cannot be picked yet). An action or fight show takes Cold Gate (`modern-dark-fantasy`) or Riot Ink (`cyberpunk`), never a soft romance or cozy preset: fights drawn soft read as weightless (Iron Pigeon ep 1). A continuing show keeps the preset it has. Without a pinned look frame its world leaks into plates, so pin the look frame or steer it with `look-note` before the plates are drawn.

Write it with the human (`docs/content-ops/templates/brief.md`) and check before the draft:

- **Premise:** a visible physical event with a small turn. Beats are what hands, bodies and objects do, in order.
- **Episode 1 alone.** Do not ask for a series arc; do not outline four or five episodes. The arc is chosen at episode 2.
- **Hook** (below) is in the first beat.

When the server says `redrafting`, `line-fit` follows the new draft; for episode 1 run `step` after it (it picks that draft up, no new draft). A series holds up to 50 named characters (unnamed background people never count); past that the server refuses by name (`new_cast_over_limit`) and gives nobody their lines. One shot shows at most 4 people. One take has at most 8 named people (the board plus a picture of each: 9 pictures in all) and at most 6 speakers on H3 Turbo, the default (each line is pre-recorded in the character's kept voice), or 3 on H3 Max and Seedance (they take only 3 voice samples); the server's writer splits takes to stay inside these. There is no cap of four on a series (Long Shadow, 15 Oct 2026, read the cast as "full at 4"): four is only the opening cast a new story is written with and the most people one shot or frame shows. A new creature or being the episode turns on (a new giant, a monster, a spirit) is a character, not a story object: name it in the note or direction at `author` with a full description so it gets a card and a picture (the server never cards a giant, colossus, monster or spirit as an object). A guest who has left (died, moved away, their arc is over) is marked as gone: `cast-exit --desk D --cast NAME --after-episode N` (one server call, any stage, free; the server checks the episode and names written episodes that still show them). In the app the creator just says it in chat. It spends nothing and redraws and re-voices nothing. Mark a guest as gone when their arc ends. Crowds stay unnamed (below).

## Hook: the first three seconds

- Frame 0 is chosen by genre; the server's writer holds the list. Its spectacle-first genres (action and fights, war-god return, apocalypse, sci-fi, mystery, horror, rebirth and regression, system levelling, cultivation, isekai, last human) open on the strongest image already moving (a power-up, a transformation, an impact, the threat): no face required. Every other genre opens on a face already moving (a hand already moving, a head already turning). Either way never an empty room, a slow drift or a still, and never a walk-in, a stare or a silent set-up.
- Every episode opens on its action and its first line together; the first line lands by about 0.5 s (server rule, founder 21 Oct 2026, all shows). The server holds it: a silent first beat in an episode that has lines is sent back once, then take 1's first line is moved onto it. Only two openings stay silent: an episode with no lines at all, and a silent opening the creator picked themselves.
- First line 10 words or fewer; no backstory in it.
- Two rules, both the server writer's: what the episode is about is clear by about 3 s; what a commitment costs is revealed only after the character commits. When the premise must land by 3 s, keep the first line to about 2 s: a 4-second first line pushes the reveal to 4 s.
- Lines 10 words or fewer; a take about 22 spoken words or fewer.
- The last beat lands one new fact, never a fade. A quiet genre may close softly.
- Never a line addressed to the viewer (a call to action, "what would you do?"). One exception: a **POV episode**, where a character speaks to the camera as if it were the viewer (a brief that opens "POV: …", e.g. "POV: your ex shows up at your wedding"), keeps its lines to the camera. That is the story, not a call to action: it is still never "comment below" or a question about the show.
- At most one spectacle beat per take; none is fine.

The server writer already follows these. The word counts come back as nudges (fictora-drama #538), printed after the draft, `author`, `line` / `edit` and a cascade preview as `note: beat 3 line runs 14 words (10 recommended) — …` under `authoring notes (nudges: nothing was blocked or changed)`, and added to `run-notes.md`. They never block, never exit non-zero, and nothing is shortened: tell the human, and the creator decides. An older server sends none. A pacing note prints as one line, `epNN pace: …` (a silent, still beat of about 2.5 s or more, or about 1.5 s or more before the next line; free, from the plan), at most once per episode on a desk: mention it to the producer once, they can keep it.

A board that opens on a wide or a pause is redrawn with that as the shape note, before any take. A weak open is never fixed by re-filming.

## Social safe zones (TikTok, Reels, Shorts)

On 9:16 the platforms cover the **top 8%**, the **bottom 20%**, and the **right 12% of the lower two thirds**.

- Faces, eyes, mouths and key props never sit there. Everything else is free; do not centre faces by default.
- Captions follow the show's caption style, which the server burns or exports: Bold (the default) sits at 76% of the height, Subtle in the band **55–70%**.
- The Sokii mark goes **top left**, just under the top strip (23:121 on 768×1344, 0.6 opacity). Never top right.

## Board gate

Open the newest `boards/` file and check (full list: [checklists.md](../../../docs/content-ops/checklists.md)):

- **Visible cause** (eye check; the server writer stages it): every action row follows a visible face reacting to its cause, or shares the frame with it.
- **Each row opens on the emotion the row before it ended on.**
- **Speakers:** a spoken line sits on a row where its speaker is in frame, medium or closer. No off-screen speaker is drawn.
- **Cast list matches the words:** a cell whose moment names one character but whose cast list has another (Hanakaze ep 4: "Catches Ren..." listing Genzō) draws the listed one. The shot list prints `!! ... names X but lists Y`; edit that frame's cast, then redraw. The same check runs **before** boards are paid for: right after the draft and at the script yes it prints `!! Before the boards: …`, and `step` (the boards draw) and `redraw-board` stop with `!! Stopped before drawing the boards: nothing was sent or paid`, naming the take, frame, row, beat and both names, with the edit that fixes it (`edit --frame <frame_id> --set subject_blocking.N.cast_id=cast_…`, or `--set story_moment="…"` when the listed cast is right). Fix the frame (free), then run the same command again. A redraw that re-authors the frames (`--note`, or a beat edit) is not stopped: it says to check the names on the redrawn board.
- **Every touch names its owner.** A cell where someone grabs, grips, holds or touches someone says whose hand (`right hand`), where that person's body is, and the side of the frame the arm comes from (`frame right`, or `his arm joined to his shoulder`). Three Payments Late t1 row 2 (10-06): "Dez clamps her wrist" on a reverse angle drew a hand from behind Noor attached to no one ($0.30 redraw). The kit prints `!! Before the boards (warning only, nothing stopped): …` after the draft, at the script yes and before a `redraw-board`, naming the take, frame, row and toucher with the free `edit --frame <frame_id> --set subject_blocking.N.interaction="…"` that fixes it; the shot list prints `!! row N: NAME "…" does not say which hand …: look for a hand or arm attached to no one`. A warning, never a stop: the server writes the owner line, the side (flipped on a reverse angle), a `no hand or arm without its visible body` ban, the speaker's open mouth, each person's look and "only these people" on every cell when it draws (fictora-drama), and the edit makes it exact.
- **Speaking mouths free.** Nothing over or at a speaker's mouth on a speaking row: no hand, cup or phone at the lips, no covering, wiping or "clearing" the mouth, no `dramatic_gasp` hand (Hanakaze ep 6). The shot list prints `!! ... hides the mouth`; edit the pose to an open gesture, then redraw.
- **An expression on every emotional row.** A row whose beat ends on an `end_state` or pays off a `satisfaction_type`, or that has a reaction cell or a close-up on a face, should wear a `reaction_kind`: the take prints it as a picture of the face that the provider rewrite keeps; without one the emotion rides the motion text, which the rewrite thins. The shot list prints `!! row N: an emotional moment ... with no expression picked` (warning only); give the beat one with `edit --episode N --beat B --expression KIND` and redraw, or say yes as is.
- **Faces after the hook.** No two insert cells in a row, and at most one insert on a take with a line (ep 6: two countertop inserts right after the hook). The shot list prints `!! N insert cells in a row`.
- **Moods carry from row to row.** A face keeps the mood it came in with: rage, then a calm "hmm" face, then rage again is a reset, not a reaction (Hanakaze ep 7 row 3: "her finger falters" was drawn calm between two rows of rage). The server carries each face's mood into the next row of the board and the take, and the writer gives every real change of mood its cause on screen (`expression_cause`); the kit no longer checks this itself. If a board still reads wrong, edit the row's pose or kind (`edit --frame N --set ...`), or name the cause (`--set expression_cause="..."`). Edits are free; redraw before paying for the take.
- **One person, one side per shot.** The cells of one shot are one continuous take: a person on the left in one cell and the right in the next is drawn twice by the video model, facing themself (Sweet Racket, 6 Oct, L-20261006-9). On a new show the server keeps each person on one side before drawing, so this is rare. When the board gate still finds it (only on boards not yet approved), it prints one line per take: `!! tK board: 2 shots may show a character twice (shot 1: Dev; shot 3: Mira). Fix: redraw tK with "keep each character on one side within a shot"` and the `redraw-board --take tK --note "..."` command once: run it before paying for the take. A stated walk across is one quiet `tK board: a character walks across the frame (shot N: X); watch that shot in the take. Information only.` line, never `!!`. Warning only; a server without fictora-drama's `board_edge_risks` prints nothing.
- **Speaking mouths.** No clench, grit, pressed or closed mouth on a speaking row. The big acting goes before the line and after it; during the words the mouth moves. Lips move on every row that carries a line; check the speaker's face is readable there.
- **Unseen movers.** Something that must never be seen moving (a statue, a doll) is banned by name in `forbidden_elements` ("no statue motion") on every frame that shows it. Then each row that shows it opens with it already in place and keeps it in the same place in both cells. The take compile enforces this, but still watch the take for a slide-in.
- **Stated moves.** A move the beat states (the statue now at arm's length) is drawn nearer in the next row that shows it, never in the same place. The server redraws only a position copied on the same setup and logs the rest, so check it by eye. On a `punchy` horror take the threat gets its own insert or point-of-view row, nearer the lens than last seen.
- **Fights: the server writes them** (Iron Pigeon ep 1, L-20261010-1; GRAFT and Iron Pigeon, 15 Oct 2026). The server's writer and take step word every fight take before anything is drawn or filmed: two or three shots, one hit per shot, coil → contact → knockback with the strike snapping back off the body (no hand left on the target, no clinch), exactly two people in the hit, feet planted, real-time speed. When it prints a take it also drops "heavy", "weight" and "slow" from the motion of strike and giant-movement shots, because they can film as slow motion; picture, sound and acting shots keep their words, and a shot that says "in slow motion" keeps it. Nothing here to rewrite by hand, but on the board still check one speed per shot (never fast and slow motion in the same shot) and clothes intact unless the story tears them; fix a row with `edit --frame` or a `redraw-board --note`. To change a fight, say what happens in `edit --frame` or a `redraw-board --note` ("he is thrown into the crates"), never how heavy or slow it is, and keep those words out of the pitch too.
- **Seams: the same close-up of the lead** (L-20261009-30). The last row of a take and the first row of the next are one close-up of the main character, on-model, face clear: the next take starts from that picture, and the face carried across stops it drifting. On a new show the server frames both sides this way when the lead is in both cells; check a seam where they are not. Not across a costume change: when the lead's outfit (wardrobe variant) changes between takes, the server leaves that seam to the writer; check the board stages the change (a time jump or the change on screen), and watch the take's first second for the old outfit. The server ends every seam with the face caught mid-expression or mid-turn, not frozen (it also starts the next take from the sharpest of the last few frames), and asks the writer to open each episode's action toward the camera where the story allows.
- **Off-screen sound stays sound** (Peanut ep 3: a crack became cracking glass). A sound whose source is not seen sits in the row's sound only; the picture shows who reacts and names what stays intact ("a neck snap off-screen, glass intact"). Panels are held positions and payoffs, never end states ("the nigiri on the plate as his see-through hand lifts it", not "the nigiri is gone").
- **Expressions** fit the moment and the right face (library in reference.md). Tears or a mood wrong across a character's episodes (crying everywhere) is `emotion`, never a shot-by-shot edit (see "Too many tears").
- **Extreme close-ups** (eye check): the server guards every board against a photo-real look. If a close-up of eyes or skin still drifts, the redraw note for that row names the show's style ("row 1 only: flat anime, clean ink lines, no photographic texture").
- **One person, twice (Turbo).** On the default lane the video model gets one picture, the board, and draws from every panel of it. The same person drawn in several panels (kneeling at the end of row 3, standing at the start of row 4) can come out as two of them in one shot, and look-alike extras read as the same face. The shot list prints `!!` when one character is in the cells either side of a cut in plainly different postures (standing, kneeling, sitting, lying, crouching, as the frame's pose says them; other poses are not guessed at). Warning only: watch that cut in the take.
- **Extras:** two unnamed people with the same face, or with the lead's stencil, is a board fault: redraw with a note giving each their own face, hair, build and stencil. Post cannot remove a duplicated person from a take.
- **Redraws.** Notes describe shapes, never judgements ("short, round, two clumsy pleats", not "crooked"). `edit --frame N --set` takes any field of the frame's brief, also one the saved frame leaves out (`expression_cause`, `story_signs`, the reaction fields: the deploy's `/openapi.json` says which); every key is checked first, and one unknown key refuses the whole command with all of them named and nothing sent. To change who is in a shot, edit the frame's staging: `edit --frame N --set 'subject_blocking=[{"cast_id": "cast_hana", "frame_position": "…", "pose": "…", "gaze": "…", "interaction": "…"}, …]'` (every person in the shot, one entry each); the kit sends the whole brief and `cast_refs` to match. To only take someone out, `--set 'cast_refs=["Hana"]'` (names or ids; the server keeps the others' staging, fictora-drama #498). Adding someone already in the episode (a line in it, or in one of its shots) the same way gives them a default staging (their side on the episode's other frames, else opposite the person already there; still pose; facing them), printed with the edit; tune it with `--set subject_blocking.N.pose="…"`. Someone only heard in the take stays out of the shot until their line is back on screen. On a deploy older than #498 only the `subject_blocking` edit works. After an exit, name the destination with their back to the portal. A plate or board refused by image moderation (more often with a child) is reported with its job id, never retried blind.
- The hook, the hand-off, the safe zones, no readable text or digits. Report brightness: information only, a dark board is the human's call. To change a board, follow "Fixing a board" below. When the human names a beat's shots, set them on the beat: `edit --beat N --shot "size|subject|camera|angle"` (repeat, 1–4; shot 1 is the beat's first row), then `redraw-board` if the board is already drawn. Never write "SHOT n —" into `--intent`. When the human names a beat's expression ("she freezes"), set it: `edit --beat N --expression freeze` (`expressions --desk D --episode N` lists the kinds and each beat's request; `none` clears), then `redraw-board` if the board is already drawn. How the speaker plays a beat's line is `edit --beat N --set delivery=KIND`, one of laughing, excited, whispered, shouted, through_tears, deadpan, trailing_off, breathless, cold (`null` for plain); the kit checks it against the deploy's list before sending and names the nearest on a typo. The shot list prints each request and `!!` when no row on the board wears it.

### Fixing a board

A `redraw-board --note` is at most 500 characters (counted after whitespace collapses, as the server counts); a longer one is refused on the desk with its length, nothing sent or booked: cut it and run it again. `redraw-plate --note` takes up to 2000. `--note` does what the app does: the human's complaint goes to the director (`POST /v1/spines/{id}/director/turns`, scoped to the take's beats), its beat edits for that take are applied (the cascade after the script gate, paid items off), the kit prints each changed row (`was` / `now`), then redraws; the server re-authors the take's frames from the edited beats, and the kit prints the rows that changed in the redraw. If the note changed no shot, it stops before paying (nothing drawn). On a server whose regenerate route takes `note` (the kit reads `/openapi.json`, and tries the note on the redraw when that cannot be read), the note rides on the redraw instead: the server re-authors the take's frames from it and draws the board with it as a correction, so even an unchanged shot list draws differently. A server that refuses the field (422 naming `note`) gets it as shot edits through the director instead, under a fresh key, and the kit says so. When the server takes the note it may draw nothing: the kit prints `!! tK: the board was NOT redrawn and nothing was charged` with the reason; nothing is booked and the old board stays. When the reason is `note_needs_detail` it prints the server's question: put it to the human, then `redraw-board --take tK --note "<their answer>"`. When the note changed a beat's shot plan, the kit says so and saves the spine again. A note counts as a change: no `--same-shots` with one. `--cause` is only a label (defaults to the note). Without a note, `redraw-board` stops with `!!` (exit 2, nothing sent or paid) when nothing the board is drawn from changed since it was last drawn: the frame briefs, the take's beats (intent, direction, shot plan, who is in them), the look notes, the cast plates, or a server stale mark from a cascade. Line words alone do not count.

1. First choice: `redraw-board --desk D --episode N --take tK --note "the human's words, as the camera should see them"` (e.g. "medium two-shot walking down the hallway, waist-up, no map"). Show the human the printed per-row changes and the new board. If it stopped because the note changed no shot (or the server drew nothing and said why), rephrase it as what the camera sees, or do steps 2–5 by hand. A question from the server goes to the human word for word; their answer is the next `--note`.
2. By hand: read the human's complaint and map it to specific rows and beats: which frame (`edit --frame N`, one row's `visual_brief`: placement, size, angle, blocking, expression), which beat (`edit --beat N --shot …`, `--expression KIND` or `--intent`), or the whole look (`look-note --add`). A wrong face on a plate is `redraw-plate`, not a board edit. A character who cries (or sulks, or rages) in too many shots is `emotion --ask "NAME shouldn't cry from episode N on"` (or the flag forms; preview, then `--confirm`), not a frame or beat edit: hand edits for emotion do not stick and cost redraws.
3. Preview each edit and show the human the before and after (after the script gate `edit … --preview` prints the cascade and changes nothing; before it, say the old and new value from `api/spine.json`).
4. Apply the edits after the human's yes.
5. `redraw-board --desk D --episode N --take tK --cause "short label"`. It redraws from the edited frames; after a beat edit the server re-authors the take's frames first. It prints what changed.
6. Look at the new board and check the complaint is gone before the board gate.

Repurposing an episode (a new idea on an episode already authored): its title and summary are updated first (no kit command yet: ask engineering), because a redraw re-authors the frames from the beats and the summary. Every frame on one board shares one location string, and a line cannot move between beats: no error says so.

Before a paid redraw that re-authors the frames (any `--note`, or a beat edit) the kit prints `!! STAGING MAY CHANGE` and the take's rows as they stand: who is in a row, its size and its role can change, and the server has no preview, so the per-row diff comes only after the draw. When the human's complaint is about one row's who, where or size, step 2's `edit --frame N --set …` is free and exact: the redraw then draws that frame as written. A redraw of edited frames alone (no note, no beat edit) prints no warning.

`--same-shots` (same as `--reroll`) only when the drawing was a random miss and the frames are right (a garbled hand, a smeared face): it draws the same direction again for $0.30. A board whose content comes from another episode (another episode's room, cast or story) is a server bug: report it to engineering with the job id; edits do not fix it.

## A take is not done until finish ran; hosted post is off

The take step always downloads the **raw** clip to `epNN/takes/take-epNN-tK-raw-vN.mp4` (model sound only, no music, no effects). With **`api_captions: true`** (default since Oct 2026), the server also **finishes the episode** after filming: concat, optional **house** caption burn on the delivered episode (~30–60 s after Fal in prod on the Modal media worker). That server burn is not the deliverable; **`finish` still runs on the laptop** for music, SFX, mix, the show's Bold/Subtle captions on the raw take, and the mark. Hosted post-production (`FICTORA_DRAMA_HOSTED_POST`) stays off, so music and effects never run on Railway. As soon as the human says Use it, run `finish` without being asked:

```bash
uv run fictora-produce finish --desk D [--episode N] [--take tK] [--take-file F] [--sfx-adjust "door=-6"] [--line-start S ...] [--line-end S ...] [--no-colour-match] \
  [--mute A-B ...] [--voice FILE@S[@DB] ...] [--cue FILE@S[@DB] ...] [--caption-label TEXT@A-B ... | --no-caption-labels] [--sign-overlay] [--prop-text "@SHOT" --prop-box X,Y,W,H ...] [--caption-style bold|subtle|plain|none] [--caption-colour yellow|white]
```

It lays the take's sound effects (from `GET /v1/jobs/{take_job}/take-facts`, never the prompt; placed on the shots as filmed, each planned shot change moved to the take's measured cut), lays no music (see **No music in delivered videos** below), matches the look to the approved board, mixes at a measured level near −18 LUFS, burns the show's captions (Bold or Subtle, below) and puts the Sokii mark top left. Every step writes a new `take-epNN-tK-<step>-vN.mp4`. Needs ffmpeg with libass. Generated audio (effects, audition clips, dry lines, Whisper timings) is made on the server by the Drama API operator audio routes (`sfx-cues`, `voice-auditions/render`, `voice-lines`, `/v1/transcripts`); no provider key ever goes on this laptop and no local file is uploaded (transcripts read the take's stored URL). Rate limits and in-progress answers are waited out automatically. If a route refuses (`operator_audio_unavailable`, `budget_cap_exceeded`), `finish` still does the look, mix, captions and mark, reports `NOT DONE` and names the refusal: tell engineering, never add a key. Costs go to `run-notes.md` only; never quote them to anyone else.

The `sfx` line names each one and why (`render failed: wrong shape: sustained cue collapses…`, `starts past the take`). Tell the human which sound is missing before they watch; never call it done without saying so. Cues left out on purpose (`--sfx-adjust …=drop`, a sound note) are listed, not flagged.
- **Locked-voice takes.** A newer server can send a Turbo take's lines, rendered in the locked voices, to the video model as its audio. The raw take's sound is exactly that dialogue track: the right voices, digital silence between lines, no ambience, no effects. Do not revoice it and do not `--mute` or `--voice` it: the kit refuses all three without `--over-locked-voices` (only for a voice the human picked after that take was filmed). `finish` lays the sound by default: the location's own ambience under the whole take (step `ambience`: one cue per episode, made on the server from the take's sound plan, i.e. the spine's frame location plus the take facts' sustained sounds, always "no music, no speech", about $0.002 a second; laid at about -28 dB between the lines in the mix, ducked 10 dB under each line and under every dry line laid on the take (a `finish --voice` line, an inner-voice thought), with the same ramps, saved in `epNN/ambience/` so a re-finish and the episode's other takes reuse it free, and take tN lays the slice that starts where tN-1 ended, so a two-take episode carries one continuous ambience across the seam), then step `room-tone`, which lays room tone only as the fallback when no ambience cue could be made (since 9 Oct the cue is worded as the app's own beds are: no hush words, only sounds that go on, an even level; a render that comes back silent or collapsing is re-made once as a steady room tone of the place, L-20261006-21) (the `ambience` step says why, and finish prints `!! no location ambience`) and always checks each line is heard in its window (by voice level, and by a saved transcript only when it is of this very take, named for its version or saved after it; a transcript of the take it replaced is skipped and the line says `levels only; transcript check skipped: …`. The transcript says whether a line was heard; the dialogue track says where: a line whose transcript words reach into its window starts where the track's own voice starts there, so Whisper stretching a first word back over the silence before it no longer reads `heard at 4.35s`); the effects on the cuts measured on the take (snapped up to 2 s from the plan; every measured cut is printed), and captions timed on the take's words: on a desk created on or after 6 Oct 2026 a transcript of the take (saved, else made once on the server, `/v1/transcripts`, $0, cached), each line on its window only where the transcript did not hear it or heard it over 0.3 s after its voice, and every caption's start moved to where its voice is measured to start on the take (never before it; earlier when the track runs ahead of its facts, L-20261005-6: the step prints `captions start with the voice …`); an older desk keeps the line windows (no transcript). The summary names the ambience (`ambience: "<description>", -28 dB …`), and the sound line gains `ambience ✓` (or `room tone ✓` on the fallback). With no room tone it prints `!! Every video the kit delivers (the finished take and the joined episode) carries voice, sound effects and room sound only, on every show, new or continuing. - A `409 hosted_post_off`, or a `503 restate_unavailable` from post-production, is not an outage: never retry it, run `finish`.
- Captions are always the English line. On a Japanese or Korean show, `finish` / `caption` show each whole English line over its speech (no word flicker); the run note says `whole English lines`.
- On such a show each whole line is timed on the **words a transcript of the take heard for it**, not on speech spans: the saved `takes/take-epNN-tK-*words-vN.json` (from `review --transcribe`), else `finish` asks the server for one from the take's stored URL (`/v1/transcripts`, a few cents). A line the transcript did not hear, or a take changed by hand (`--voice`/`--mute`, or a `--take-file` after `trim`/`tempo`/a sound step or of unknown origin), is timed on speech spans as before.

With no transcript it is timed on speech stretches in order and prints **`EXTRA SPEECH: … not captioned: a-b s`** when stretches are left over: watch the captions, then transcribe, rebuild the take's audio when the stray speech is wrong dialogue (Hand sound, below), or set `--line-start` / `--line-end`.

A `--take-file` made from the raw take only by `freeze`, `soften`, `deboard` or `colour` keeps its sound timeline, so the raw take's transcript still times it (`finish` follows `epNN/takes/edit-chain.jsonl`, or the run notes on an older desk; the report prints the chain). The `captions` report line and the run note say what timed each line: `(words)`, `(speech)`, `(manual)` or a mix like `(words start, manual end)`.
- On a 30 s or 60 s episode each take is captioned with **only the lines of the beats it plays** (split as the board and `check-lines` split them, from the spine's storyboard pattern); `caption --take F` does the same for a `take-epNN-tK-…` file and captions every line on a file not named for one take (a joined episode). If the split cannot be read (an older desk with no pattern, or a pattern that does not match the desk's takes), the take gets every line as before and the report prints `TAKE LINES: …`: check those captions by eye.
- Caption still off? `--line-start S` and `--line-end S`, once per line in order (either or both), on `finish` and `caption`. A hand end is exact: no hold, no reading minimum.
- **Caption style: Bold or Subtle, one choice per show (user decision, 6 Oct 2026).** **Bold** (`bold`, a new show's default): one short line at a time (two or three words, split above ~12 characters, never across a clause mark or a breath), Arial Bold 92 on a 1080×1920 canvas (1.44× the old size; 64 on a 1344-high take), white with ONE word in house yellow `#FFE500`, outline 7 and a heavier shadow, the line's bottom at 76% of the frame. Each word appears when it is said (never more than 80 ms early): the chunk is laid out whole and its unsaid words are transparent, so it never moves as it fills. The yellow word is the line's writer-marked emphasis when the spine gives one (the optional `emphasis_word` on a dialogue line), else the chunk's main word (the last content word, an ALL-CAPS shout first, never a function word; a one-word chunk is yellow only when the word carries meaning). A chunk too wide is set smaller, never wrapped. **Subtle** (`subtle`; `house` is its older name and still works): the yellow Arial Bold 64 word flicker (up to three words build up, then reset), bottom at 62%, wrapped onto two balanced lines when long. A voice heard, not seen (a line marked `off_screen`, any line of a `voice_only` cast member, an inner-voice thought, or a line laid with `finish --voice` that is not a script line, such as narration) is the same face in italic (Arial Bold Italic) in either style, at that style's size, colours and place (in Bold: white with its yellow word, chunked the same way): only the slant changes, so one episode never mixes caption fonts (since 9 Oct 2026; it was Georgia italic, which put a serif line among Arial captions in Sweet Racket ep 5). Never re-burn a kit caption at another size: 45 on a 1344-high take IS the house 64 on 1920 (`captions.py` scales by height), so a re-burn at 64 is 1.4x house size, not the rule. When the human wants bigger captions, `finish … --caption-scale 1.25` (or `caption … --caption-scale X`, 0.5-2) sets every caption line bigger and the kit wraps and places it; never edit the .ass by hand (sed line breaks wrote stray `N`s, L-20261008-5). A letterbox show keeps its own caption band whichever style is set.
- **Asked once, at the look approval, never blocking.** The first time a NEW show's look is approved (`approve --gate look`; on a desk that drew no look frame, its first plates yes) the kit draws a free still, `shared/look/caption-preview-vN.png`: the approved look frame (else the first plate, else the first board) with the show's first dialogue line in Bold (left) and Subtle (right). Show it and say "Captions default to Bold; reply 'subtle' to switch." `caption_style: bold` is saved in `production.config.json` at once, so silence is Bold. On "subtle": `caption-style --desk D --set subtle`. A continuing show (a desk with finished episodes) is not asked: it keeps `subtle`, the captions its episodes went out with (saved the same way), unless the human switches (`caption-style --desk D --set bold`). A desk whose `caption_style` is already set (older desks saved `house`) is never asked, and neither is a desk created before 6 Oct 2026 (it keeps `house`). `caption-style --desk D` prints the show's style and why.
- **No em or en dash in any burned caption** (user rule, 6 Oct 2026). The script and the voice keep their dashes (the voice reads one as a cut-off); what is drawn on the picture does not: a dash ending a cut-off line or chunk is an ellipsis (`Please—` shows `Please…`, in word flicker too), a dash between words is a comma (`D-9341 — do not` shows `D-9341, do not`), an opening dash is dropped. **The server draws these words** (21 Oct 2026, decision D7): every caption cue and title the kit burns (`finish` / `caption` captions, inner-voice captions, the hook line and title bar, the letterbox title band) is sent to the server's on-screen text route and burned exactly as it comes back, after timing (word timings are unchanged). The kit keeps no copy of the rule: a server without the route stops the command with a plain message (update the server). Sign overlays (redrawn lettering in the shot) are not captions and keep the sign's text. Never type a dash into a caption by hand either.
- `--caption-style bold|subtle|plain|none` on `finish` and `caption` overrides the show's style for one run: `plain` is white whole lines (Subtle's size and band), `none` no captions (the take is still complete). The show's style is `caption_style` in `production.config.json` (above).
- **Letterbox shows (4:3 takes) get their 9:16 file from `finish` and `join`** (founder decisions, 6 Oct 2026; layout matches the "Not Home" reference; the server uses the same numbers). Black 1080x1920 canvas, the picture at 1080x810 in the middle; the Sokii mark in the top black band (never on the picture); the title block (Not Home's 56 px Arial Bold) just above the picture: the setup line white (the series title), the hook line house yellow (`--hook-line`, else the `hook-line` pick, else the spine's); captions (Not Home's 56 px Arial Bold, one line preferred, centred on the frame unless that would cross x 950) in the band under the picture, yellow by default (`--caption-colour white`, or `letterbox_caption_colour` in the desk config), in phrases of up to five words with no word left alone, ending when the voice ends on a locked-voice take, upright when the take draws a speaker whose line is flagged off screen. `join` puts the mark and title on the joined file once (`--hook-line` / `--no-hook-line` there too). `review` reads only the picture on a letterbox file (its opening, frames, cuts, board and tail checks never measure the black bands). The 4:3 takes stay on the desk. Never build the 9:16 file by hand. Portrait shows are untouched. Full table: [reference.md](reference.md) → Finish → Letterbox deliverable.
- **System panels** (system and game genres only: `system_leveling`, `last_human`, `isekai`, `cultivation`, `regression_revenge`): the writer's status windows, level ups, quest notices and gate warnings on beats (`beats[].system_panels`, look `system_panel_look`). `finish` burns them after the captions as the server placed and drew them (typewriter reveal, in the picture, out of the safe zones); `--no-panels` skips them, and is the way through on an older server that cannot draw them yet. Never choose or rewrite one for the creator. Full rules: [reference.md](reference.md) → System panels.
- **Choosing the hook line** (the big text on the first ~3 s, or a letterbox show's yellow title line): `hook-line --desk D --episode N --list` (free, no call) shows the writer's options; `--pick K`, `--text "..."` or `--off` stores the human's choice on the server where the app reads it (free). Read the options to the human and let them pick: a line that spoils the twist is a real fault. The script gate prints the hook line's words, where it goes and every option, with a ⚠ when the twist option is selected (L-20261005-11, 7 Oct 2026): read the words to the producer, never only a yes/no. On a new story the server's default is the stakes or rule line, never the twist. On a letterbox show, `--setup-line "..."` (60 characters at most) sets the episode's own white title line (`--default-setup-line` goes back to the series title), alone or with a hook-line choice. On an older server the pick is kept on the desk for `finish` and `join`, and the app still shows the server's.
- **Inner voice.** Each take lays the thoughts saved with `inner-voice` that start in it (step `inner-voice`). Cue times are seconds on the episode as filmed; where each plays is the server's answer: `finish` sends each take's real length (ffprobe) to the server's free thoughts route, which places it the way the server's own join does (a cue past a seam stays on the take where it starts, with `!!`). **Every thought plays in black and white** (step `thought-grey`, before the mix and captions): the spans the server greys (cues and the script lines it reads as thoughts) with the server's own filter; captions stay in colour. `join` asks the server again with the real lengths and names a take finished before this with `!! … plays in colour: … Run finish on tN again (free …)`; it never greys a captioned picture itself. An older server without the route: no grey, a printed note, never an error (its cues are named as not laid). The dry line is made on the server in the thinker's locked voice (`voice-lines`, same key and ledger unit as `voice-line`; reused from `epNN/voices/` on a re-run, never paid twice), laid at the cue like `--voice` (effects and, on a locked-voice take, the ambience duck under it) and captioned in italic where it plays. A thought spoken in the show's language under an English caption: `inner-voice --cast X --text "<English caption>" --spoken-text "<the words said>" --at S` (as `voice-line --text/--spoken-text` and `line --spoken/--subtitle`). The server's cue holds the caption (`line`) and the spoken words (`spoken_text`, drama #1017), listed as `[says: …]`; `finish` sends them to the voice and captions the English line in italic. The voice is made on the server for that cue (`line_id`), with the acting direction the server keeps for the thought (listed as `[acted: …]`); the kit sends none of its own. A thought whose `--text` is not English is named (`!! … plays uncaptioned`) by `inner-voice` and by `finish`. A desk made before #1017 still reads its `epNN/inner-voice-spoken.json` for a cue the server holds no words for. A thought plays at a dialogue line's level unless asked: `inner-voice … --db -3` with a new thought, or `inner-voice --cue ID --db -3` for one already saved (free, nothing sent; kept in `epNN/inner-voice-levels.json`, listed as `[-3 dB]`), and `finish --thought-db N` moves every thought of the take on top of that (-24 to +6 dB; default 0). After `voice --pick`, the next finish speaks every episode's thoughts in the new voice (the desk's current voice, not the episode's older snapshot). No locked voice, a refusal, a line past the take's end, an earlier take not on the desk or a cue after the last take: the rest finishes, the cue is named, `inner voice ✗`, `NOT DONE`.

## Hand sound: stray speech, a new line, a missing cue

Times are seconds on the take **as filmed** (the raw take): `deboard` keeps the timeline while `finish` works, and the held head is cut off last with everything laid on it, so nothing is shifted by hand. Each flag repeats.

- **A line missing, wrong, repeated, invented or on the wrong shot (model voices): re-film the take** (founder decision, 8 Oct 2026; L-20260924-10). On a take filmed in the video model's own voices (`Soundtrack: native`, or a show on voice mode `model`), `finish` first compares the take's transcript with its script (step `[lines]`; the server's Whisper transcript of the stored take, made once and saved on the desk, $0) and **STOPS before making anything** on a fault: `MISSING LINE`, `WRONG WORDS` (with what was heard), `REPEATED LINE`, `EXTRA SPEECH` (invented words; fillers such as "um" and Whisper's "thanks for watching" never count) or `WRONG SHOT` (an on-screen line heard mostly outside the shot the take facts put it in). It prints the take, the line, what was heard and the re-film command: `film --desk D --episode N --take tK --cause "…"` (prices it, about $0.40 a take), then the same with `--confirm-spend` after the human's yes; exit **5**. Show the human the stop text and ask for that yes. **Do not patch a spoken line** with `voice-line` + `finish --voice`: a laid line breaks lip sync. Only a line heard **off screen** (no lips) may be patched that way, and only as the human's explicit choice: `finish` then prints `!! … laid by hand … allowed only because it is heard off screen`. A hand line over an on-screen line never clears the stop. A matched line passes with small wording differences (70% of its words, or Japanese / Korean characters, heard in order; numbers, punctuation and apostrophes normalised); a line under 3 words (5 ja/ko characters) the transcript missed prints `CHECK BY EAR`, never a stop; so does a longer line the transcript missed when the take has voice where it should be (a quiet line, Noodle24 L-20261008-38; a truly dropped line leaves its window quiet and still stops). Each fault and each `CHECK BY EAR` line gets a short clip cut from the raw take, `epNN/takes/listen/epNN-tK-lineN-<kind>.wav`, printed beside it (`[lines] listen: …` and under `Listen before choosing` in the stop): play it to the human before asking for a re-film. `--mute` over invented speech clears an `EXTRA SPEECH` only for stray words between lines (never for a line). To deliver a faulted take anyway (the human's call, logged in the run notes as `ACCEPTED WITH FAULTS`): `finish --accept-line-mismatch tK`. When no transcript can be read or made, finish prints `!! line check NOT RUN: …` and carries on: listen to every line. Locked-voice takes are not word-checked here (their words are checked before filming).
- **A line in the wrong mouth: `SPEAKER NOT ON SCREEN` stops `finish` on both voice modes** (founder decision, 12 Oct 2026; Dead Heat ep 2, Don't Look, Hana ep 6). The video model moves whichever mouth is on screen when a line plays. So `finish` checks each line against who the take facts say is in the shot under it (`shots[].people.named`): the moment it was heard on a model-voice take (the transcript's words), its window on the locked-voice track on a locked-voice take (locked takes are now checked for this, though not for their words). An on-screen line heard mostly over a shot that shows other named people and not its speaker STOPS like the other line faults (`SPEAKER NOT ON SCREEN: line 2 (Sota) … over shot 1 (…), which shows Hana, Cabin Woman but not Sota`), with a listen clip (`…-lineN-speaker_off.wav`), the re-film command and `--accept-line-mismatch tK`. A line spilling a moment into the shot before its speaker's cut never counts. Before re-filming, check the board row draws the speaker, or mark the line off screen, or the re-film lands the same way. An off-screen line (a character's, or a background shout the server marks off screen) over a shot with named faces prints `!! line N (…) is heard off screen …, over shot K …: Moretti may mouth it`: a warning, never a stop. Watch that shot's mouths and re-film or cut away if one moves. So does a background shout with no flag over a shot of named faces only. `!! speaker check NOT RUN` means the server sent no people per shot (older server): watch each line's mouth yourself.
- **Before filming**, the `film` price prints `!! epNN tK: Sota says "…" on board row R, which draws Hana, Cabin Woman but not Sota` (an on-screen line on a row without its speaker) and `!! … (off screen) says "…" on board row R, which draws only Moretti` (an off-screen line over a single face). Read from the desk's spine (each beat's anchor frame and its row's cells): the server returns no per-shot people before a film. A warning only: fix the row (draw the speaker, add a cutaway or a second face), mark the line off screen, or give it to someone drawn there, then redraw, or tell the human and film.
- The rest of this section is mix notes, never a re-film.
- **Wrong take dialogue** (garbled fake speech between lines, a stray mumble; a line said wrong on a model-voice take is a re-film, above): never mute a range. A muted range leaves a hole in the background (the take's own room sound drops out). Drop the take's audio and rebuild it: a `voice-line` for every line (below), an ambience `cue` the length of the take ("<the place> ambience, no music, no speech"), then `finish --mute 0-<take length> --voice FILE@S … --cue AMBIENCE@0`; the effects are laid as usual (no music). The kit has no one-flag way yet (backlog). A locked-voice take needs none of this: its audio is only the locked lines, and `finish` lays the ambience and bed.
- **A new or changed line: off-screen lines and thoughts only, in the script first** (decision D4, 21 Oct 2026; an on-screen line said wrong is a re-film, above). Add the line to the script first (`line --add --beat N --speaker NAME --text "..." --off-screen`, or a thought with `inner-voice`), so the script's rules check it. Then `voice-line --desk D --cast X --text "..." [--episode N] [--spoken-text "..."]` makes one dry line in X's locked voice on the server ($0.10 per 1,000 characters, Whisper-checked) into `epNN/voices/`. The server refuses, before any spend, a line that is said on screen or is not in the episode's script, and an older server is refused by the kit before anything is sent. Play it to the human, then rebuild the take's audio as above with the new line among the others (never `--mute` just the old line's range). It is levelled to −18 LUFS unless `@DB`; the bed ducks under it like speech. A line that would run past the take is refused.
- **A sound the take's Sound lines missed:** `cue --desk D --episode N --description "a descending comic brass sting" [--seconds 1.5]` makes one cue on the server (~$0.002 a second) into `epNN/sfx/` and prints its RMS per half second and shape check. A creature or monster cue is written plainly ("a monster as the door opens"): the server adds the words that keep it from coming back as a pet or a person (fictora-drama #826); a server without that stops with `server too old for cue`, nothing spent. Then `finish --cue FILE@S[@DB]`: −8 dB under the take unless `@DB`, 10 dB lower while someone speaks, clamped to end 0.15 s before the take does. A hand cue on a visible action goes with the drop for the same auto sound (`--cue …door-slam…@5.25 --sfx-adjust "door=drop"`), or the door slams twice; `finish` prints `!!` with the drop to use when a hand cue lands within about 1 s of an auto cue of the same sound.
- **Impacts and sound notes (server).** With fictora-drama #462 live, the take facts' cue plan also lays each impact the story's action states (a beat's `end_state`, a row's `chain`, `ends` or `sound`: "a dry stone crack", "the door slams shut") once, as a short cue on the shot that shows it. With #467 live, a sound note on the story (`POST /v1/spines/{id}/sound-notes`) can add one sound to one take ("add a dry stone crack at the end of episode 1 take 2 row 4"); an add note that names no take is `422 sound_note_needs_take`. Both reach only take facts fetched after them: for a take already filmed, `take-facts --refresh` reads its facts again (the sound-note bullet below).
- One cue per visible action, on the frame where the action lands. A cue with a bad shape is rendered once more with a changed description, then dropped with a line in the run notes; a missing cue never blocks a take. A quiet cue: raise it in 2–3 dB steps with `@DB` until it reads.
- `finish` checks every hand file before any step: missing, silent, or outside the take is an error and nothing is written. A hand step that then fails prints `NOT DONE` like missing effects.
- **A sound the human wants added to a take** ("add a dry stone crack at the end"): `sound-note --desk D --episode N --take tK [--shot S | --row R] "add a dry stone crack at the end"` saves it on the story (free); on a take plain words work and one note may name several sounds ("a quick blush puff, and a tiny sweat-drop drip"), up to 8 added sounds per take and 16 per episode (fictora-drama #481). A take already filmed keeps its saved facts until `take-facts --desk D --episode N --take tK --refresh` reads them again (a new version; the old file stays) and prints the cues it adds; then `finish` again. `finish` prints `!!` when its facts are older than the sound notes. The server's refusal is printed by name with the fix (`sound_note_needs_take`: pass `--take`). A drop or level note (`sound-note --desk D "no purring"`, "the door slam is too loud") reaches every take the same way: with fictora-drama #475 the take facts leave the dropped cue out and give a levelled cue its dB offset, and `finish` lays that plan (never applying the note a second time); a take already filmed needs `take-facts --refresh` first, which prints each level change (`~`) and drop (`-`) with its note id. `finish --sfx-adjust "door=-6"` / `"hum=drop"` stays as a change for one take only, on top. A sound no note can place (a sting, a wordless making take) is a hand cue. Full cue guide: [sound-cues.md](../../../docs/content-ops/sound-cues.md).
- Never loudnorm a take.
- `finish` saves the mix buses beside the mix (`take-epNN-tK-mix-vN-{raw,ducked,key}-bus.wav`, mono 48 kHz, about 0.3 MB a second together): `review` measures the duck depth from them.
- A take that will be re-filmed gets no `finish`, no cues and no voice lines.

## Salvage before re-filming

A flawed take is saved with a free edit whenever one hides the flaw; a re-film is paid and is the last resort (Gallery Heiress review, 12 Oct 2026: takes were re-filmed or scratched that a free edit would have saved). Before you ask for a re-film, tell the human which free edit would fix the fault and offer it first; make it after their yes, and show the result.

| The fault | Free edit to offer first |
| --- | --- |
| A short mistake mid-take: a character drawn twice for a moment, a glance at himself, a glitch. On screen about **0.5 s or less is always a cut, never a re-film** | `trim --take-file FINAL --cut A-B` on the shot change |
| A mistake at the start or the end | `trim --episode N --take tK --start S --end E` (the handles; no file is cut) |
| A shot that holds the mistake too long, or drags | `tempo --take-file FINAL --factor 1.5 --from S --to S` (only that shot) |
| A jump cut, or a stray element (an extra, a double, a hand) at the edge of the frame | `zoom --factor 1.2 --center X,Y --from S --to S` before `finish` (punch in on the shot) |
| Scenes or takes in the wrong order | `join --take-file F2 --take-file F1` in the right order |
| Garbled text the video invented | `blur` (a patch, reported) or `finish --sign-overlay` |

Straight to a re-film (no free edit hides it): a smear or melt on a face (a blood-looking smear across a face), the wrong character or identity for the whole take, the double on screen for most of a shot, a spoken line missing or wrong on a model-voice take (lip sync, "Hand sound" above). `film --take tK --cause "…"` prints `!! salvage first` under the price when the cause reads like a fault a free edit fixes ("twice", "out of order", "jump cut", "stray", "half a second"): say that free edit to the human before asking for the yes.

**Keep decent rejected takes.** A take that is decent but wrong for its scene (a good wide, a clean reaction) may fit another scene later in the series. Before re-filming it, `keep-take --desk D --episode N --take tK --note "what is good in it and where it could go"` puts it on the desk's reuse list (`shared/reuse-takes.jsonl`; free, local). `keep-take --desk D --list` prints the list: read it when planning the next episode.

## Review a take: the numbers before the verdict

```bash
uv run fictora-produce review --desk D [--episode N] [--take tK] [--take-file F | --file F] [--board B] [--words-json J | --transcribe] [--json]
```

Free and local (ffmpeg + numpy); only `--transcribe` asks the server for a Whisper transcript of the take's stored URL (a few cents). Without a file it reads the newest finished file for the take, else the newest raw take, and the block's first line says which. Run it on the raw take as soon as it lands (before `finish`, that is the default), before asking Use it or Change this, and again after `finish` before handing it over. It prints one block (and appends it to `run-notes.md`): paste it into the verdict. Each section is ✓ or ⚠ with the threshold it used (`–` when there was nothing to measure). It always exits 0: a ⚠ is something to watch for, never a stop, and never by itself a reason to re-film. Under the block it prints the free edits to try before any re-film, with this take's commands filled in.

- **Loudness:** a raw take below −30 LUFS needs cues; a finished one sits at −20 to −15 LUFS with true peak ≤ −1 dBTP. Duck depth (6–12 dB under the voice) from the mix buses `finish` saves; a take finished before this kit wrote them reads `not measured`: finish it again.
- **Cuts:** hard cuts vs the take facts' shot changes. An extra cut is a soften; a missing one is often a camera move: look.
- **Frames:** frozen stretches (a stall, or your own `freeze`) and stacked double frames: look at each full size.
- **Board:** head board frames on a raw take are what `finish` removes; any board frame mid-take, or at the head after deboard, is a fault.
- **Lines:** the `check-lines` output as it prints it (the count, each line's shot and board row, `!!` for an on-screen speaker out of frame), then each approved line heard, `MISSING` (the one real re-film; on a model-voice take `finish` stops on it and on wrong, repeated, extra or wrong-shot lines, see **Hand sound**) or, for a line under three words, `CHECK BY EAR` (listen; never a re-film on the transcript alone). Cast names match sound-alike spellings. A Japanese line matched on the server's readings reads `(by sound, NN%)`.
- **People:** the head count per shot the take facts expect (`On screen: 2 people (Hana, + 1 unnamed)`; the same lines print after filming and in `take-facts`). Nothing is detected: count the people in each shot by eye (and on the zone sheet of a finished file), and watch the cuts where a character changes pose. The same person on screen twice: salvage first (on screen about 0.5 s or less, or one short shot: `trim --cut` it or `tempo` past it; only at the edge of the frame: `zoom` away from it); a re-film with the cause `same person rendered twice at shot N` only when it stays on screen. An older server sends no head counts: the section says so in one line; count by eye anyway.
- **Safe zones** (finished files only): the caption box on sampled frames vs the covered zones and the 55–70% band; it writes a zone sheet (covered zones shaded) for the face check by eye.
- **Opening** (take 1 of every episode; `finish` prints the same ⚠ lines for take 1): a dark frame 0 (luma under 0.10 on frame 0 and over the first 0.5 s), a static first second (mean frame-to-frame change under 0.006), and no face on frame 0 (two local OpenCV detectors, real faces and anime/manhwa faces, unioned, the anime one first on an anime/manhwa show; the take facts' head count only when OpenCV fails to load, printed as `!! face detector unavailable`). The face check is skipped when the opening beat has no spoken line (a wordless opening on a place or a thing is fine). Warnings, never a stop: read them to the human. `join` prints them for the joined episode too.
- **Ending** (`join` prints it for the joined episode): more than 0.3 s settled after the last line or action. The cut should land on the peak.
- Not measured: what must not be on screen per board row. Check that by eye. Thresholds and how to read each number: reference.md.

## Local edits: deboard, soften, freeze, zoom, trim, tempo, blur

Free, on this laptop (ffmpeg + numpy). Each writes a new `take-epNN-tK-<step>-vN.mp4` and a run note; nothing is overwritten. Details and thresholds: reference.md.

- **Board frames.** A Turbo take opens on a frame or two of the still board. `finish` now removes them first (`deboard`), the only automatic edit to footage: it holds a frame over them and never cuts: measured against the approved board, capped at 12, replaced with the first real frame so the length and sound do not move (take-facts cues and captions keep their times). Those clones are a held still before the first motion and **never ship** (founder, 13 Oct 2026: the first seconds are what keep a viewer; cut, never freeze), so when the server set no trim handles `finish` cuts them off LAST, like a handle, exactly at the first real frame (picture and sound together so lips stay in sync, captions moved, a `handles` edit with source `kit-deboard` in the record, so `join` and `review` move every time with it). The hook card does not stop the cut. A line whose voice starts under the board frames loses that sliver: the report says `!! the first line's voice starts at … under the board frames`; listen to its first word. A `--take-file` made by `deboard` is cut the same (the edit chain records how many clones). None found: nothing written. `--no-deboard` only when the human wants the board opening kept. `CAP HIT` in the report: look at the head at full rate.
- **What the server did at the ends** (`review`, Board section): `server held N start / M end frame(s) · original kept: <url> (sha256 …)` (the provider's untouched take is kept: `review --original` downloads it, checks its sha256 and length, and writes `take-epNN-tK-original-compare-vN.mp4`, held left, original right); `held frames but no original stored (before fictora-drama #559)` on an older take; `!! possible board frames at the start/end (N) left as filmed: <reason>` when the server was not sure. Never call that last one "held 0". The kit does not hold an end the server left as filmed either: `deboard` stops with `Refused` and `finish` skips its deboard with a `!!`. Look at that end with the human; only if it is the board, `deboard --hold-unsure` and `finish --take-file` the result.
- **Order.** raw → `deboard` → `soften` / `freeze` / `zoom` → `finish --take-file <that file>` → `trim` / `tempo` on the finished file → watch.
- `zoom --factor 1.2 --center X,Y --from S --to S` is a **punch-in**: the picture closer around a point (frame-grab the moment to measure), scaled back to full frame, for that window (the whole take without `--from`/`--to`). Same length, sound copied, so the raw timeline holds. It hides a jump cut (punch in on the shot after it) or crops a stray element out of the edge of the frame. Run it before `finish` (deboard first); a finished file is refused, since its captions and mark would zoom too. Keep it at about 1.3x or less on a 768p take, and watch the window at full size.
- `soften` always after `deboard` (the board-to-motion jump reads as a cut). No `--cut` detects hard cuts itself; say which cuts it found.
- `freeze --at S --hold S` keeps the length: the held frame covers the picture, the sound plays on.
- **Trim handles** (fictora-drama #563; the server's, not a file cut): `trim --desk D --episode N --take tK --start S --end E` sets where the take starts and ends when it plays (one of `--start` / `--end` alone moves only that end; the other stays where the handles are now) (seconds on the take as filmed, the take-facts times; at least 1 s; snapped to a frame, said when it snaps); `--reset` puts back the automatic handles (just past the board frames the server held); `--preview` shows the change and sends nothing. It prints the handles now and new, what each end loses, and a `!!` for every line or effect the window cuts, then ends on `Applied` or `Refused: <reason>` (a named server code gets its fix). Nothing is billed and no file is cut; it saves the take facts again. Needs the producer's yes like any trim. `finish` then lays everything on the take as filmed and cuts at the handles LAST (the take before the mix, the master, the marked file, the captions' `.ass`; a new finish record with a `handles` edit), so `join` joins the take at its handles like the server; `join` and `review` read take-facts times on such a file minus `start_s`. A trim made in the app reaches `finish` after `take-facts --refresh`. Handles that are the whole take cut nothing; an older server sends no handles and nothing is cut.
- `trim --cut` only on the finished file (`--take-file` is required), and only after the producer's yes: no trim or cut of footage without it. Show what was cut (the times and the frames either side). Check the first frame after the cut at full size. A finished cut shorter than its band (e.g. 14.2 s from a 15 s episode) is allowed: say the new length; it is not a deviation.
- `tempo --factor 0.9` only for a show cut slow, and only on the finished file: `finish` lays effects at the filmed times.
- **Captions ride along.** An edit of a finished take (`blur`, `freeze`, `soften`, `trim`, `tempo`, the handles) writes the master's `.ass` beside the edited master too, re-timed the way the picture was (same times for blur / freeze / soften; a trim drops the cues inside the cut and moves the rest earlier; a tempo scales its window), and prints `- Captions: A.ass -> B.ass (…)`, so the edited take stays captioned. `!! captions NOT carried` means the edited take has no captions file: finish the take again, then edit again.
- Keep the un-marked master (`…-cap-vN.mp4`); the marked `…-sokii-vN.mp4` goes out. Previews, rough cuts and "just combine" files are made from finished takes and carry the house captions too.
- An overlay added in post (a `blur` box, a title) never covers the key reveal: render test frames of the key shots first and look at them.
- `blur --box x,y,w,h --from S --to S` is a **patch** for garbled readable text the video invented (a sign reading "…nakaze Swettes", a shop name that is not a word) when re-filming is not worth it. Run it on the finished file. Boxes are pixels of the take (top-left x, y, width, height; frame-grab the moment to measure; must lie inside the frame); cover the whole sign with a margin and the whole time it is readable. Hard edge by default: a feather that fades INTO the box leaves text readable, so `--feather PX` only softens outside the box. Watch the window at full size. Always report it (learnings row + the reply): it hides the symptom, the server should stop making the text.

```bash
uv run fictora-produce soften  --desk D [--take-file F] [--cut S ...]
```

## Join: the 30 s / 60 s episode and the series cut

Free, on this laptop. When an episode has a second take, offer the join as soon as every take is finished; a series cut is the same command across episodes.

```bash
uv run fictora-produce join --desk D --episode N                  # every take of N, newest finish each, in take order
uv run fictora-produce join --desk D --episodes 1 2 3             # series cut -> shared/cuts/
uv run fictora-produce join --desk D --take-file F1 --take-file F2   # these finished takes, in this order
uv run fictora-produce join --desk D --take-file T1-sokii --take-file T2-recap --from-record T2-cap   # a re-captioned copy stands in for its recorded master
uv run fictora-produce join --desk D --episode N --ending freeze-black   # optional: hold the last frame, then black
```

- It reads the record `finish` leaves (`take-epNN-tK-finish-vN.json`): each take's sound before the mix and its un-marked captioned picture. **No music goes under the join** (delivered videos carry none); a take an older finish left with music in its own sound is named with a `!!` line (finish it again for a no-music join), never refused; captions ride on their picture; the mark goes on **once**, on the joined file. The un-marked master stays beside it.
- Takes of one episode meet on a straight cut (they hand off on the same frame); episodes meet on a 0.25 s dissolve. `--dissolve S` sets every seam; say so when you use it.
- Each take gets one gain to the takes' median level, then one measured mix gain and one limiter. No loudnorm.
- Refused before anything is written: a take that is not finished (every take on the desk needs a complete finish), a take not at 24 fps, mixed sizes. The joined file is counted at 24 frames a second.
- Each seam's room-level step is printed. Over 5 dB, `join` first fixes the seam itself, free and on this laptop, the way it was fixed by hand every time (8 sightings across four series: Fated in the Rain ep 4 −19.4 → −1.4 dB, ep 3 −13.6 → −6.1 → +4.7 dB, Hanakaze ep 2 +11.1 → +1.9 dB). (a) A **steady bed** under the 2 s on the quiet side of the cut: the show's own steady sound, one already used in this episode first (its location ambience in `epNN/ambience/`, a sustained planned effect, a sustained hand cue in `epNN/sfx/`), then the series' (another episode's, steady-named files in the desk's `sfx/`), then room tone made from the takes' own quiet passages (else band-limited room tone). A file is used only when it is steady (3 s of sound, levels within 14 dB); the level is computed from the measured gap (the quiet side to 3 dB under the loud side), never over −22 dB, with a 0.05 s ramp at the cut and a 0.5 s fade away from it. (b) If that is not enough and the quiet take's head (or tail) is near-silent before its first line or sound, a **trim** of that silent stretch on the last filmed cut inside it (never into speech, never more than 40% of the take); the join is built again and the bed laid again. The join is mixed again from the same sound at the same take gain with the bed added before the one limiter, so nothing outside the seam windows changes, and a bed that does not make its seam smaller is not laid. When every seam now passes, the join completes and the report says `SEAM FIXED by join (free): <seam> <before> -> <after> dB` with exactly what was laid and trimmed (also in the run notes and `--json` `seam_fix`): tell the human and have them listen through that seam. When it still fails: `SEAM FIX TRIED`, every attempt listed, `NOT DONE`, exit **5**, the master as first joined is kept to listen to and nothing is marked; do not hand it over. What is left is by hand: a steadier sound that belongs in the scene on the quiet take (`finish --cue`), a `trim` of the dead air on a filmed cut, then join again, or `--accept-seam "why" --accepted-by NAME` when the step is a line on the cut, not the room. `--no-seam-fix` measures and refuses as before; `--accept-seam` behaves as before (no fix is tried). Desks created before 6 Oct 2026 get (a), the steady bed, only (founder, 7 Oct 2026): never (b), the trim, which cuts picture with the sound; when the bed is not enough there, `join` says `no silent-head trim` and refuses as before (trim by hand, then join again).
- `trim` / `tempo` (and `freeze` / `soften` / `blur`) on a finished file apply the same edit to the take before the mix and the un-marked master and write a new finish record (the edit chain in `edits`), so the edited take joins at its new length; the newest record wins, so `--episode N` joins the edited take. A file no record names (edited from a raw take, or while a record file was gone: the edit says `No finish record`) is refused: finish again, then edit. Never join the -sokii files by hand (that stitches two beds and two marks).
- A take finished before `join` existed has no record: run `finish` on it again before the join.
- A copy of a finished take with only the picture changed (re-captioned) has no record either. Pass `--from-record <the -cap master it was made from>` after its `--take-file` (the Nth `--from-record` goes with the Nth unrecorded `--take-file`). `join` checks it has the same size, frame count and sound as that master, joins its picture over the record's sound before the bed, and writes `SUBSTITUTED: … stands in for …` in the run notes. A copy of the marked `-sokii` final is refused (it would be marked twice): make the copy from the `-cap` master.

## Show voices: locked or the model's own (one choice per show)

Whose voices a show's takes speak in is the show's choice, kept on the server (founder decision, 5 Oct 2026), so a season never changes voice actor between episodes:

- **locked** (the default for a new show): each line is rendered in the character's locked voice (cast card) and the take films to that track. The Voices gate applies.
- **model**: the video model voices each character from the cast card's voice description, as every take did before 2 Oct. No Voices gate (there is no locked voice to hear), and the kit films a model-voice show with `music_by_finish`, so the video model is asked for no music (delivered videos carry none).

A show that never chose keeps the voices its filmed episodes used: any episode filmed with the model's own voices keeps the show on `model`. `step`, the estimate and `film` print `Voices for the next take: …` with the reason; `voice-mode --desk D` prints it on its own (free).

**Ask at the start of every new episode on a continuing show.** Before `author` / `brief` for episode 2 on (and when you pick up or bind a desk that already filmed episodes), run `uv run fictora-produce voice-mode --desk D`. When it says the video model's own voices (earlier episodes filmed with them, or set for the show), ask the human, word for word:

> Keep the same voices as earlier episodes (recommended) or switch to locked voices?

- Keep (the default; also when the human does not choose): `uv run fictora-produce voice-mode --desk D --set model`. It stores the choice so it never moves; there is no Voices gate.

## Change a character's voice (never regenerate)

"The voice feels off" is a voice change, not a new story and not a new video. Never re-draft or re-film everything for it. The same commands run the Voices gate before the first take: audition, pick (the pick is the human's yes), or keep the voice as it is.

```bash
uv run fictora-produce voice --desk D --cast NAME --audition [--episode N]   # 4-10 candidates on their real lines, about $0.02-0.05
uv run fictora-produce voice --desk D --cast NAME --audition --text "…" --voices Rachel,Aria,Sarah   # any wording (≤300 chars), read by exactly those voices
uv run fictora-produce voice --desk D --cast NAME --pick N                   # after the human picks (N or the voice's name); free; records their yes
uv run fictora-produce voice --desk D --cast NAME --keep                     # the human keeps the locked voice; free
uv run fictora-produce voice --desk D --keep-all                             # the human keeps every speaking voice; free
uv run fictora-produce voice --desk D --list                                 # each speaking voice and whether it has a yes; free
uv run fictora-produce revoice --desk D --cast NAME --episode N --take tK   # each filmed take they speak in
uv run fictora-produce finish --desk D --episode N --take tK --take-file <take-epNN-tK-revoice-vN.mp4>
```

After a voice change, `revoice` the takes already filmed that the character speaks in (rules below), then `finish --take-file` on each. Play the listening reel (`shared/voices/<cast>/audition-vN/reel-vN.m4a`; `reel-vN.txt` says where each numbered candidate starts) to the human; a second audition set needs `--cause`. `--text` is any wording up to 300 characters, on the spine or not (on a Japanese or Korean show, written in that language); `--voices` is exactly the Eleven v3 voices the human named, read in that order, one candidate each (`--count` is ignored). Both go to the server as they are; a broken rule comes back as a named refusal before anything is spent (`voice_audition_unknown_voice` lists the catalog; also `_voice_count`, `_text_too_long`, `_text_language`): read it to the human and ask again, never swap a voice yourself. A retired premade (`Bella`) resolves to its catalog stand-in and a repeated name is auditioned once. A set that already holds the wording and the named voices makes a new reel for free. Picking a candidate does not change the script: if the new wording should be said in the episode, `edit --line-id` the line too. On Turbo (the default) a take with `Soundtrack: native` (or none: an older server) does not carry the locked voice, because voice references are not sent: revoice each such filmed take the character speaks in, including takes filmed after the pick. A take with `Soundtrack: locked voices` already speaks in the voice locked when it was filmed: never revoice it for that; only a voice picked after it was filmed needs `revoice --over-locked-voices`, and takes filmed after the pick carry the new voice as they are. Only on R2V do takes not filmed yet use the new voice as they are. Re-film only a take where the dub does not sit (lips visibly wrong, a shouted line), with a cause and a stated cost; never the other takes, never the story.

An off-screen voice (speaker, phone, radio) played over another character's face is heard as that face speaking: give it a source in post with `voice-fx --file F --range A-B [--range C-D ...] --preset intercom|phone|radio` (local ffmpeg, $0, one new file at the same level; repeat `--range` for every line in one call), then `finish --take-file` on it (captions are timed on the revoice words).

If a line is still reported "not heard", pass `--words-json` or re-film only that take. A short line (three words or fewer, "Blinking!") the transcript missed is placed on its planned window instead (the soundtrack's line window, else the planned shot timing from the take facts) and printed `!! … used its planned window A-B s`: listen to it. A short line better shown than heard: `finish --caption-label "Blinking!@A-B"` captions it with no spoken line.

## Recovery

- Video stuck ~50% in post: `fictora-produce cancel-job --desk D --job-id job_video_…` and stop. Never `retry-video`, never `--confirm-spend` again.
- A job the server has stopped updating: while any job runs (draft, plates, boards, a redraw, video), the kit watches its `updated_at` and progress. When neither has moved for 10 minutes it prints once (and again every 10 minutes) `WARNING: The server has not updated this job for N min (last update HH:MM UTC). It may be stuck: …` with the `status` and `cancel-job` commands. Slow jobs keep moving; a frozen one is likely stuck on the server. Check `fictora-produce status --desk D`; to stop it, tell the human and `fictora-produce cancel-job --desk D --job-id <id>`. The kit never cancels or retries by itself, and the usual deadlines still hold. Filming (`film`, `step`) watches the take jobs and clips too, and its warning starts `video job job_video_…:`. It also reads `/v1/video-generations/{id}` each poll and stops at once, with the server's code and message, when that route says failed or cancelled even while `/v1/jobs` still says `running 0%`; never `--confirm-spend` again while a film is stuck.
- A film job stuck with every take filmed (the job sits at ~50% and does not move while its take jobs are done; NOCLIP ep 1, L-20261006-4): `fictora-produce collect-takes --desk D --dry-run` says what it would collect, then `fictora-produce collect-takes --desk D` collects. Spends nothing (GET only). It collects only when every take the film asked for is filmed (counted against the takes asked for, never the job's own growing list) and the job has not moved for 10 minutes, or the server failed the job after every take was filmed; otherwise it says why not yet and when to try again. Several film jobs waiting, or a `film` the desk let go after the server failed it: `--job-id job_video_…` (from the run notes). Never write `api/17_raw_scene_clips.json` (or any clip record) by hand or fetch the take jobs yourself; tell engineering the job id.
- `cancel-job` answers `terminal: false` when the cancel is only requested: it says the job has not stopped yet and that steps already started on the server may keep running for a while (a server fix is in progress), waits 15 s, reads the job once more and says its status. Do not send the cancel again, and never enrol another take while it runs.
- A redraw, `author` or `rewrite` run again after its saved job was cancelled (`cancel-job`) or ended failed starts a fresh job under the next attempt's key and says `Job … ended cancelled; it is not picked up again` (a redraw re-sends its note). The server films without them and draws no plate (fictora-drama #517); nothing to do. `422 spine_reuse_invalid: cast.<id>.visual_brief is required` on the film means a deploy older than #517 (nothing charged): give them a line back (`line --add --beat N --speaker NAME --text "…" --off-screen`), film again, tell engineering. Never work around it with raw HTTP.

## Learnings: after every video, without being asked

The human makes episodes through this kit only and cannot see the server or app code. Never ask them to open or check it; say how sure you are about where a fault comes from.

**Each run.** When an episode is accepted, abandoned or stops partway, write or update `learnings.md` in the production folder (beside `run-notes.md`, shape from [templates/learnings.md](../../../docs/content-ops/templates/learnings.md)), then add the same items to the running ledger `~/Downloads/documents/fictora-learnings/ledger.md` (create it the first time; save its path to your memory). One item each:

- **ID** `L-YYYYMMDD-n`; **series / episode / stage** (brief, script, cast, look, board, take, finish, captions, sound, export)
- **What happened**, in plain words, and **cause**: `confirmed` (the kit or server said so) or `suspected` (say why). No guesses about model internals.
- **Fix belongs in**: `server` (refused, wrong answer, wrong render), `kit` (a command or script here), `app` (seen in the Sokii app), `runbook rule` (nothing broken; do it differently), or `unsure`
- **Cost** (re-renders, dollars, minutes), **evidence** (job ids, the command, the exact error code; never prompt text), **workaround**
- **Kind**: `bug`, `issue` (works, badly), `fix` (a change that worked), `learning` (a rule for next time)

A learning names the cause and changes what is typed next time. An item already in the ledger is not added again: append "seen again: <series> ep N, <date>" and raise its count. A clean run writes "no new learnings"; never invent items. Then tell the human in two or three lines what you added and ask: "Anything you want to add in your own words?"

**Their own words stay separate.** Anything the human adds, asked or not, goes verbatim into `~/Downloads/documents/fictora-learnings/my-notes.md` with the date and series. Never rewrite or merge it into your items; if it names the same problem, add a `see L-…` link and keep both.

**Offer the composite.** At the start of a session and after each video, count ledger items not marked `shared`. If any: "You have N learnings from M runs since <date> that haven't been shared. Want the composite?" On a yes, write `~/Downloads/documents/fictora-learnings/composite-YYYY-MM-DD.md` (a new dated file, never an overwrite; also publish it as a page if you can publish Artifacts here):

1. Top: repeats first, by count, then anything that cost money
2. Server, Kit, App, Runbook rules, Unsure: bugs before issues
3. Fixes that worked
4. Producer notes (<name>), verbatim
5. Runs covered: series, episodes, dates, re-render cost

After the human says it was sent (write-ups go to the addresses in [README.md](../../../docs/content-ops/README.md)), mark those items `shared: <date>`. An item seen again after sharing is flagged "seen again after sharing". A product gap still gets its [backlog.md](../../../docs/content-ops/backlog.md) line when the series closes; the ledger does not replace it.

## Setup check, one plate again, the ledger

- **Run the kit from bash** (or zsh), never PowerShell: its quoting breaks `--set '…'`, `--note "…"` and JSON arguments.
- **First thing on a new laptop:** `uv run fictora-produce setup-check`. One ✓/✗ line each: the API token set and accepted (one free authenticated read), ffmpeg and ffprobe, libass (captions), the filters the finish and edits use, Arial Bold and Arial Bold Italic (the caption faces), Python 3.12+, uv. Any ✗ exits 1: fix it before the first paid step. A ⚠ on Arial does not block: every caption line is then set in the kit's bundled Liberation Sans (Arial's metric twin, the face the app's captions use) and `finish` prints `WARNING FONT: …`, never a silent mix of fallback faces. Install Arial to match the house face exactly. It never prints the token.
- **One character's plate again:** `fictora-produce redraw-plate --desk D --cast NAME --note "…"` (the note on that character, then their plate alone, $0.30; stage table above). `plates --cast NAME --cause` is retired: it prints that pointer, exits 2 and sends nothing. When a plate redrawn with `--note` still shows the old look, add `--fresh`: the server draws the character from their card like a first plate, with no reference to the old plate (same price). A server that cannot do it yet says so plainly and nothing is sent or charged: tell engineering, and redraw without `--fresh` meanwhile.
- **Book by hand with a unit:** `fictora-ops spend --desk D --episode N --usd X [--take tK] --unit look-frame` (or `voice-line`, `cue:gaan-sting` …). Every booking also lands in `spend_log` in `series.json` (episode, take, dollars, unit, time); the kit's own bookings name their unit.
