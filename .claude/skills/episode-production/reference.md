## Work on a story made in the app

A creator's app story belongs to their app account. To make its next episode from a desk:

1. `uv run fictora-produce stories --title "Hana"`: find the story id (read only, spends nothing).
2. `uv run fictora-produce start --spine-id ID [--series "Desk name"]`: the server lists the new desk on the story; the creator stays the owner, so the story stays in their app library and the new episode shows there. The desk reads cast, episodes, show language, art style and caption look from the server.
3. Make only the next episode (`author --episode N`). Never re-film or edit the creator's earlier episodes, and never publish for them.
4. `uv run fictora-produce detach --desk D` when done: the desk can no longer read or write the story; the story is unchanged.

## Phase machine (`fictora-produce`)

One machine per desk, pointed at one episode (`episode_ordinal` in `production.json`; `status` prints it). `author --episode N` points it at episode N with its lines at the script gate. `epNN` below is that episode.

| Phase | Next move |
| --- | --- |
| `new` | `step` → draft |
| `ready_cast_enrol` | `step` → cast plates + downloads to `ep01/plates/` (episode 1 only; books $0.30 a plate). Refused, nothing sent, while a drawn look frame is not approved (`approve --gate look`) |
| `wait_plates` | Human yes → `approve --gate plates` |
| `wait_script` | Human yes on the lines (printed by the draft or `author`; `epNN/api/spine.json`) → `approve --gate script` (episode 1: the whole spine; episode 2 on: `pilot-episodes/{n}/approve`) |
| `ready_boards_enrol` | Refused, nothing sent, while a drawn look frame is not approved. `step` → boards to `epNN/boards/board-epNN-tK-vN.png`, brightness (information only), the shot list row by row with the line spoken on each row and its speaker (`!!` when the speaker is not drawn on that row or is placed off-frame; off-screen lines are fine), safe-zone warnings; books $0.30 a board |
| `wait_board` | Human yes → `approve --gate board` (the boards `step` drew; `--path` only for a board it did not draw). Or edits, then `redraw-board` ("Fixing a board" in SKILL.md) |
| `ready_estimate` | `step` → this episode's estimate, and only this episode (earlier episodes are not filmed again): the server's dated dollars, else the price table (then a loud `!! SERVER ESTIMATE FAILED` line first); always names the lane and $/s; says "$X of a $Y envelope" (warn only) |
| `wait_spend` | Human yes → `step --confirm-spend` |
| `ready_video` | (internal) take enrol |
| `complete` | Every take of the episode raw on disk (`epNN/takes/take-epNN-tK-raw-vN.mp4`) with its take facts (`epNN/api/take-facts-epNN-tK-vN.json`); spend booked from the facts; video and take job ids in `run-notes.md` → `finish` per take, then the next episode |
| `failed` | Read `last_error` in `production.json`; see Recovery |

The harness auto-retries `plan_media_spine_version_stale` (cast, boards) and retryable `authoring_stalled` (draft). Any other failed job, and any refused request, stops with the server's own code, message and rule details (for example `authoring_validation_failed at frames[3]: …`, or a take refused because it would drop an approved line): read it to the human; do not re-run blind.

## Aligned or deviation

Before any paid step, say one word: **aligned** or **deviation**. If deviation, post before doing it:

```
DEVIATION — this is not the product flow
What I'm about to do: <the thing>
Why the API can't:     <the endpoint or field that refuses it>
Product gap:           <one line for docs/content-ops/backlog.md>
Extra cost:            <$ and minutes>
```

Always a deviation: a finished episode longer than its 15 / 30 / 60 s band; any route with no command here; hand-rolled HTTP. Editing product code or settings is never acceptable. Not a deviation: a finished cut shorter than its band after trimming (e.g. 14.2 s from a 15 s episode); takes still film at the normal clip length, so say the new length and carry on. Aligned, with commands (below): episode 2 on (`arc`, `brief`, `author`), line edits (`line`), beat and frame edits (`edit`), board redraws (`redraw-board --note`: the note rides on the redraw where the server takes it, and becomes shot edits through the director where it does not (a 422 on the field falls back by itself); or put the change in first with `edit --frame`, `edit --beat` or `look-note`; with nothing changed and no note it stops unpaid unless `--reroll`), one character corrected and redrawn (`redraw-plate --cast NAME --note`; when the note's own spine change makes the draw fail `plan_media_spine_version_stale`, it reads the spine again and draws once more under a fresh key, never sending the note twice; the old `plates --cast --cause` is retired and only prints that pointer).

## Script gate

- Compare every brief line with the spine. The writers may cut or rewrite a line. The draft `step` prints the brief's lines against the script (`kept`, `rewritten`, `cut`, `added`, matched by speaker and wording); show the human each line that is not `kept` beside the spine line. A "keep exactly" line that changed is a fault: fix it before the gate with `line --line N --text "…"`. A cut line goes back with `line --add --beat N --speaker NAME --text "…"`.
- **Keep exactly.** The sentence "Keep these lines exactly as written." (or "verbatim", "word for word") inside the brief's Lines section locks every row of that section's tables and any `Speaker: "line"` quoted there. Fill the beat and the `### Take N` heading so the server knows where each line goes. The spoken line is locked (founder decision, 1 Oct 2026): the server puts a trimmed, reworded, silenced or reassigned locked line back on its beat, and on a Japanese or Korean show pins the brief's original as the performed line (`spoken_text`) before localizing, so only the subtitle may adapt (the brief's own subtitle is kept as `brief_subtitle_text`). The draft report lists `spoken: N locked` and every `subtitle adapted`; a `!! BUG … the spoken line changed` row should never appear: put it back with the `line --spoken` it prints and tell engineering. Locked lines that cannot fit (one beat holds ~4.9 s, about 12 English words; a take speaks ~11 s; one line per beat) are never shortened: the draft stops before any writer runs with `locked_lines_out_of_bounds`, naming each line and its overrun, and `step` prints `PAUSED for the creator`. Ask the creator to shorten the line or move it to the next episode, `bind` the edited brief (or `brief --edit` it), `step` again. A line locked in another language than the show's (an English line on a Korean show) pauses the same way with `locked_line_not_in_show_language` (fictora-drama #650): `step` prints `PAUSED for the creator` with the server's words; ask the creator for the line in the show's language, word for word, or to unlock it, then `bind` and `step` (the same brief re-run shows the pause again and pays nothing). In the draft report a locked line counts as `kept` only when its `spoken_text` and `subtitle_text` are the brief's as well as its script; otherwise it is counted `rewritten` and its row says what is said or shown differs. The draft's idempotency key carries a hash of the brief and its draft settings (words, language, band, preset, cut tempo, lane), so the edited brief is a new draft (`bind` prints `The brief changed: the next step drafts the new brief`); `step` with the brief unchanged shows the same pause again from the old plan job and sends nothing, and a step re-run after a dead session still never pays twice. A locked opening line keeps its words: past 10 it is only a `first_line_long` note, never refused. **When a line doesn't fit (fictora-drama #962):** a newer server does not stop bare. For a locked brief line, a line approved in a picked direction (episode 2 on), a `line` edit or a `brief --edit`, it writes a fitted version that follows the house dialogue rules and stops with `line_needs_creator_choice` and a card: the reason in plain words, the creator's lines, the fitted (or trimmed) lines with any action under a short reaction, and the choices. A draft job's error carries it in `details.fit_proposals` (cause `needs_creator_choice`; the old `locked_lines_out_of_bounds` comes first for older kits); a line edit or brief answers 409. `step`, `author`, `line` and `brief --edit` print the card under `PAUSED for the creator`; `fictora-produce line-fit --desk D [--proposal ID]` shows it again (free). Show it to the creator word for word and run their choice with `line-fit --desk D --proposal ID --choose use|trim|edit [--edit @lines.txt]` (`--edit` file: one `slot: line` each, slots as the card shows them in brackets, or JSON `[{"slot", "text"}]`). The server answers `applied` (the story is saved on the desk), `needs_choice` (an edit that still does not fit: a new card) or `redrafting` (the draft starts again with the chosen lines: `line-fit` follows that job; for episode 1 run `step` after, which picks it up and sends no new draft). The kit keeps no fitting rule of its own: never trim, split or reword the lines yourself. An older server keeps the old pause above. **Script contract (fictora-drama, 9 Oct 2026):** the brief's Lines (or Script / Dialogue) section is the approved script even without the lock sentence: after every first draft the server puts back its trimmed, reworded, moved or dropped lines and their speakers (a dropped minor speaker's short call-out comes back as a background shout), on every show and language. The lock sentence still adds the pause for a line that cannot fit. Whatever the draft still says differently prints after `step`/`author`/`rewrite` as `SCRIPT: …` with the `line` command that puts it back: ask the human, never fix it silently.
- **Authoring notes** (fictora-drama #538): the server's word-count nudges, printed after the draft, `author`, `line` / `edit` (only the ones the edit introduced) and a cascade preview, per episode and take, and added to `run-notes.md`: `line_long` (a line over 10 words), `take_words_over_target` (a take over about 22 spoken words), `first_line_long` (a first line over 10). A code the kit does not know is printed by its message. Never a stop, never a non-zero exit, never shortened by the kit: show the human and let the creator choose. A silent opening (no first line, beat 1 silent) is valid. An older server sends none.
- Show each line in the language it will be spoken, with the translation beside it.
- **Japanese / Korean:** the register follows who speaks to whom (staff to customer is 申し訳ございません / 정말 죄송합니다, not ごめんなさい). No English quip carried word for word. No notice-board noun stack in speech (「逆襲中止！」 "counterattack cancelled!") unless the character is really announcing. The server repairs that one form once; everything else is your check. Pin the exact performed line (`spoken_text`) so localization does not rewrite it. A dialect (Kansai-ben, Busan satoori) needs a native speaker's yes before the script gate; if nobody can check it, write the standard language.
- **Captions** are English only for now (house style). Japanese / Korean captions are deferred. A line whose caption (`subtitle_text`, else `text`) is not English (kana, CJK, Hangul, any non-Latin letter, CJK/fullwidth punctuation) is timed but left uncaptioned; `finish` (on its `captions` summary line) and `caption` print ``NOT ENGLISH: <line id> "…" — add an English subtitle with `edit`/`line --subtitle` ``.
- **Heard, not seen:** an `off_screen` line, any line of a `voice_only` cast member, or an inner-voice thought laid by `finish`, is captioned in the house face's italic, Arial Bold Italic (same face, size, colour, edge and place as House; the Italic ASS style), so one episode never mixes caption fonts (since 9 Oct 2026; Georgia italic before). A line flagged `off_screen` whose speaker the take draws (the take facts' shot, the board frames' `cast_refs`, the redrawn board's note) is set upright on portrait and letterbox takes alike (`italics: …` in the captions report). Arial is a system font (macOS ships it); without it every caption line is burned in the bundled Liberation Sans (assets/fonts, SIL OFL), Arial's metric twin, and `caption`/`finish` print `WARNING FONT: …` and add it to the run notes. `--caption-scale X` (0.5-2) on `finish` and `caption` sets every caption line X times the style's size.

## Characters and age

Characters may be any age: children, teenagers, adults, the elderly. Write the real age ("10, primary-school kid", "16", "28") and the plate draws it. Digits are preferred; the server reads an age in words ("sixteen", "twenty-six") correctly, so it is not a warning.

The hard line: never romantic, sexual, suggestive or fan-service framing of anyone under 18. Their age and body are never sexualised, and they are never in a romance arc (no love interest, crush, dating, or someone else's romance aimed at them). A romance lead is 18+. The server rejects a breach as `minor_in_romance_arc`. A child is also never in a romantic, sexual or intimate scene, not even as a bystander: a beat or frame that puts someone under 18 on screen (its cast, blocking, an unnamed child figure, the beat's mover or on-screen speaker; a line heard off screen does not count) while its staging is intimate (making love, undressing, a kiss between adults, a romantic dinner …; family affection such as a goodnight kiss on the forehead is fine) is refused as `minor_in_intimate_scene` at authoring, `edit`/`line`/cascade, board admission, the estimate and film admission, before anything is paid. The kit prints each scene (`episode 1 frame 4 (frame_ep01_04): Mina is under 18 and on screen; "they kiss" makes it intimate`) and its fix: move the child out of that shot (`edit --frame F --set 'cast_refs=[…]'` naming everyone else) or change the scene so it is not intimate. Never age the child up to keep the scene. PG staging (no kissing, embracing or face contact) applies to everyone. Asked for a minor in a romance: say no and offer the character at 18+ or the relationship as non-romantic.

Children on camera (P0): camera at or above the child's eye level, falls feet-first or seated with legs together, leggings or shorts under coats and dresses; checked on the take before captioning (runbook, Characters and age).

## Off-screen voices

Declare them in the brief's cast table as voice only (an intercom, a phone, a grandfather in the back room). They are never drawn: not a sleeve, a hand, a cane or a shadow. An off-screen voice over another character's face is heard as that face speaking; give it a source in frame or a source treatment in post. Once every one of their lines is off screen and no frame shows them, the server flags the card `voice_only` and draws no plate (fictora-drama #469, which supersedes #453); the kit leaves them out of `plates/` and the plate count. They need no visual brief either: the look, boards, video reuse and episode authoring skip them (no `cast_visual_brief_missing`). A voice that also appears in a frame, or whose line goes on screen, is drawn again and owes a plate and a visual brief like anyone else: check the plate count before the spend. A character nothing reaches once the spine has frames (no line, vocalization, inner-voice cue or frame) and with no visual brief, such as a voice whose only line was removed, gets no plate and does not block filming (fictora-drama #517): the kit leaves them out of the plate count too. One with a visual brief (written for a later episode) still owes a plate. `line` still refuses stranding a voice unless `--strand-voice`, and `film` / `step` print an `info: stranded_voice` line; only a deploy older than #517 refuses the film (`422 spine_reuse_invalid … visual_brief is required`, nothing charged). A character's thoughts are not an off-screen voice: `inner-voice --desk D --episode N --cast NAME --text "…" --at S [--until S]` sends `PUT /v1/spines/{id}/episodes/{n}/inner-voice` (the episode's whole cue list: `cue_id`, `start_ms`, `end_ms`, `speaker_cast_id`, `line`); `--remove N` / `--clear` / no flags to list. Times are seconds on the episode as filmed (take 1 at 0). It spends nothing and leaves the lines and the script yes alone. `finish` lays and captions each cue on the take it starts in (the `inner-voice` step below).

## Shot plan per take

Pick the plan from the scene, not one default for every show.

| Plan | `--cut-tempo` | Use for |
| --- | --- | --- |
| One continuous shot | `one_shot` | Inner monologue, a making or process take, a walk |
| Coverage, 3–4 shots, one per board row | `punchy` | Romance, horror, comedy, any two-hander where a reaction lands |

Coverage: a wide, a face close-up, and an insert or point of view; no two neighbouring rows at the same size and angle; the reply on the listener's angle. A row with a spoken line keeps only `locked`, `dolly_in`, `dolly_out`, `pan_*`, `tilt_*` or `handheld` (lips stay readable); arcs, orbits, trucks and cranes go on silent rows. One spoken line per beat, nothing else happening during it. End on a wide for the hand-off.

A beat's own shots, when the human names them ("open on her hands, then the wide from above"): `edit --beat N --shot "extreme close-up|her hands|handheld" --shot "wide|the shop|locked|high angle"` (1–4 shots, each `size|subject|camera|angle`, camera and angle optional; or `--shot-plan '<json>'` / `@FILE`). Shot 1 is the beat's first board row; a beat owns the rows up to the next beat's first row. On a row board the server writes each shot's size and angle onto its row and the frames author stages the subject and camera; a 3×3 board reads the plan in the prompt only. The plan wins over the coverage the frames author would pick. It replaces the whole plan; `--clear-shot-plan` hands the choice back to the frames author. The script printout and the board shot list show each beat's plan. Never write "SHOT n —" into `--intent` any more (still followed, but not a field). A speaking row still keeps a lip-safe move. To change only a beat's camera move, one edit does it: `edit --beat N --set camera=handheld` (or `'camera={"move":"handheld"}'`; plain words such as `push in`, `static`, `handheld jolt` are read as the move). The server keeps the beat's own end framing and intensity (fictora-drama, Iron Pigeon L-20261014-10); a row's own camera is `edit --frame F --set row_direction.camera_move=handheld`.

## Preset and look

`--preset-id` is needed even when the look will be our own frame. Pick the nearest; for horror that is `modern-dark-fantasy` (Cold Gate). The horror preset `horror` (Dead Light) is a draft on the server: its proof draws are not made, so it cannot be picked yet. Once a look frame is pinned (`approve --gate look`, or `look --url`), the preset keeps only its shot composition; its world, palette, finish and reference images are dropped from every drawing. Pin before the plates: anything drawn before the pin carries the preset's world.

## Expression library

A character who cries (or keeps one mood) in too many shots is not fixed here: use `emotion --ask "NAME shouldn't cry from episode N on"` (or its flag forms: no-tears rule or mood for an episode range, kept by the server); hand-editing tear kinds shot by shot does not stick and costs redraws.

The writers pick an anime expression (`reaction_kind`) for every emotional moment. When the human names one for a beat ("she freezes when he says it"), set it on the beat: `edit --episode N --beat B --expression freeze` (a kind or its label; `--expression none` gives the choice back to the writers). `expressions --desk D [--episode N]` lists what the deploy offers (`GET /v1/capabilities`, comedy kinds marked) and what each beat asks for; spends nothing. The kit checks the kind against that list before sending. The server gives it to the beat's anchor frame (both frames of its row on a row board), so the board draws its marks and the take plays it. Before the script gate it is a plain patch; after it, a cascade that marks the take's board for `redraw-board`. The script printout shows `expression: KIND` under the beat and the board shot list shows `beat N asks for expression KIND`, with `!!` when no row on the drawn board wears it. You check it at the board gate. Any kind may go on any beat, whatever the genre: the scene decides (the comedy mark is information, not a limit). Still open on the server: the request does not say whose face wears it on a two-person row (check the face on the board; fix it with `edit --frame … --set …`).

| Kind | Marks that must be drawn |
| --- | --- |
| `laugh`, `big_laugh` | open laugh; big: huge open mouth, tears at the eye corners |
| `happy`, `sparkle_delight` | closed crescent eyes (^^), sparkles, blush |
| `slow_surprise`, `dramatic_gasp`, `double_take` | eyes widen late; gasp; look, look away, snap back wide-eyed |
| `stunned_blank`, `shock`, `freeze` | blank white eyes or shrunken pupils, jaw drop, white-out, body locked |
| `sweat_drop`, `embarrassed`, `blush_look_away` | sweat drop, blush stripes, steam, eyes away |
| `anger_flare`, `comic_anger`, `eye_twitch`, `pause_then_outburst` | cross vein, sharp teeth, steam, red aura; the twitch; a held beat then the burst |
| `smiling_rage`, `smile_goes_cold` | eyes OPEN, tiny trembling pupils, eyelid twitch, shadow over the upper face, vein, too-wide clenched grin. The smile stays: never blank white eyes, never a scowl |
| `gloom` | vertical tatesen lines, colour drained, a dark cloud, on a VISIBLE face |
| `deadpan` | dot eyes, flat-line mouth |
| `deflated` | chibi squash, soul drifting out |
| `comic_tears`, `tear_up` | waterfall tears; welling eyes, wobbling mouth |
| `flinch` | a small recoil |

- **Pick by the moment, not the genre.** Never a comedy face on a grief or horror beat (Noodle24: a grieving nurse drawn beaming with dot eyes; Don't Look, Hana: `deadpan` on a horror beat). Any kind may play in any genre. The symbolic kinds (`happy` through `deflated`) fit a light, awkward, petty or comic moment, even in a serious show (a sweat drop at an awkward pause in horror). Real dread, grief, danger or tenderness gets the plainer kinds.
- **Whose face.** On a cell with two or more people, the writers name the face that wears the kind. A listener's expression on a speaking cell plays whole and silent on the listener. Wrong or missing face, or a wrong mark: fix the frame (`edit --frame … --set …`), then `redraw-board`.
- On a speaking cell the expression plays before the first word and after the last; during the words the mouth moves.

## Social safe zones

| Zone | Where | Covered by |
| --- | --- | --- |
| Top strip | top 8% of the height | tabs, search, camera |
| Bottom band | bottom 20% of the height | post caption, username, music |
| Right rail | right 12% of the width, lower two thirds | like, comment, share |

- Faces, eyes, mouths and key props never sit in a zone. Bodies, hands, floor and set may run through. Off-centre and two-shots are fine; do not centre faces by default.
- There is no face detector: look at every cell of the board. The boards `step` lists (`look at row R cell C: …`, never `!!`) a frame whose written placement could put a face or prop in a zone. Written words are not a finding (they raised 3 false alarms as `!!` lines): look at that cell, and at every other cell, since a face drawn into a zone with clean words is not listed. `review` sends the finished take's burned caption file (`.ass`) to the server's caption check, which lays out every cue and prints each finding with its times. Captions are never found by colour: yellow scenery (a raincoat, a lamp) is not a caption. On an older server the kit reads the file itself and prints a `NOTE`. A face or key prop in a zone: fix the frame's placement (`edit --frame … --set …`), then `redraw-board`.
- Captions follow the show's caption style, with the server's numbers: Bold text bottom at 76%; Subtle block in 55–70% of the height, bottom at 62%. `finish` and `caption` wrap a too-wide caption onto two balanced lines (only one too long for two is set smaller).
- The Sokii mark: top left, just under the top strip, `23:121` on 768×1344 (x = 3% of width, y = 9% of height), 0.6 opacity. Never top right.

## Board checks, in full

- The rows follow the declared shot plan.
- **Visible cause.** Every action row is preceded by a visible face reacting to its cause, or shares the frame with it.
- **Opening emotion.** Each row opens on the emotion the row before ended on. A calm smile right after the sign breaks reads wrong.
- **The picture shows the rule.** A change the viewer must see as a jump (the statue is closer) goes in its own row: H3 blends the cells of one row into one move.
- **Speakers.** A spoken line sits on a row where its speaker is in frame, at medium or closer. No off-screen speaker is drawn. The shot list prints each row's line and speaker and a `!!` when the speaker is not drawn there; fix it with `line --off-screen`, `line --speaker`, or `edit --frame` then `redraw-board`.
- **What the server already did.** After the frames author, a speaking row framed wider than medium is tightened (to a medium two-shot, over-shoulder medium or medium close-up) and logged; off-screen lines and silent rows keep their width, so wide geography goes on a silent row. A row's direction speaks only the line anchored to that row, and the anchored row stages its speaker saying it. The script writer is told which rows each beat plays on: on a one-take row board three beats on four rows play on rows 1, 3 and 4 (beat 1 keeps row 2), not 1, 2, 3. A character added to a frame is staged from their own nearest frame, and a pose or gaze filed under the wrong character is replaced, both logged. These are logs, not board warnings: still read every row.
- **Speaking mouths.** No clench, grit, pressed or closed mouth on a speaking row. Big acting before and after the line.
- **One person, twice (Turbo).** On the default lane the video model gets one picture, the board, and draws from every panel of it. The same person drawn in several panels (kneeling at the end of row 3, standing at the start of row 4) can come out as two of them in one shot, and look-alike extras read as the same face. The shot list prints `!!` when one character is in the cells either side of a cut in plainly different postures (standing, kneeling, sitting, lying, crouching, as the frame's pose says them; other poses are not guessed at). Warning only: watch that cut in the take.
- The hook (frame 0 already moving: the strongest image on the server's spectacle-first genres, a face on every other genre; SKILL.md, Hook), the hand-off frame (a frame with picture, never a fade or black), no readable text or digits, safe zones.
- Brightness is information only, never a block: report it; a dark board is the human's call. (`--accept-dim` is accepted and ignored.)

## Prompt policy

- The compiled video prompt and the compiled image prompt behind every plate and board are proprietary and stay on the server. Never fetch, save, print or quote `GET /v1/jobs/{id}/provider-spec` (operator tokens get `403 provider_spec_internal_only`).

## Reading a take

Measure, then watch: every approved line heard, exactly; cut count (compare consecutive frames); loudness (dialogue about −15 to −20 LUFS); brightness vs the board; every beat present in order. Write every fault, including the ones you will not fix. Then ask **Use it** or **Change this**.

- A missing spoken line is the one real re-film. Name the cause first.
- A line the take was never asked to say is a server fault: `fictora-produce check-lines --desk D --episode N [--take tK]` names it from the take facts (never the prompt). Report it with the take job id; do not re-film blind.
- `check-lines` also prints, for every line the take was asked to say, the shot and board row it fell in. A `!!` line means an on-screen line landed on a row whose frames do not draw its speaker (off-screen lines are fine). That is a board fault, not a take fault: fix the frame or the line and redraw the board before re-filming. When the take has a different number of shots than the board has rows, the rows are not matched and the frame check is skipped.
- **Duplicate people (Turbo).** The video model films from the board picture alone, so a person drawn in several panels can appear twice in one shot (the kneeling pose from one row and the standing pose from the next, at once), and look-alike extras can merge into one face. Count the people in each shot against the take facts (`review`'s People section, the lines after filming, `take-facts`: `shot N (a-bs): On screen: …`), and watch every cut where a character changes pose. Found one: re-film that take with `--cause "same person rendered twice at shot N"`. Post cannot remove a person.
- Stray mumble, garbled fake speech or a wrong line is not a re-film and not a muted range (that leaves a hole in the background): drop the take's audio and rebuild it (SKILL.md, Hand sound).

## Review: the numbers

`fictora-produce review --desk D [--episode N] [--take tK] [--take-file F | --file F] [--board B] [--words-json J | --transcribe] [--json]` reads one take and prints one block with six sections (seven on a finished file), each ✓ (inside its threshold), ⚠ (look at it) or `–` (nothing to measure, and why). It exits 0 whatever it finds; 2 only when the command itself fails (no take, no ffmpeg). Local and free, except `--transcribe`, which asks the server for a Whisper transcript of the take's stored URL (a few cents, saved as `takes/take-epNN-tK-raw-vN-review-words-vM.json`; nothing is uploaded). The transcript records the media it was made from (the raw take's sha256 and its stored URL, `kit_source`), and only a transcript of exactly the take being read is used: one named for that take version, one recording that take's content and URL, or an older unversioned one saved after that raw take. After a re-film the old take's transcript is never reused: `--transcribe` makes a new one, and without it the Lines section says `saved transcript not used: the only transcript, `…`, is of take v1, not `take-epNN-tK-raw-v2.mp4` (re-filmed since)`. An unchanged take keeps its transcript (no second charge). The Lines section names the transcript and the take version it belongs to (`transcript: `…` (of take v2, `take-epNN-tK-raw-v2.mp4`)`). Without `--take-file` (alias `--file`) it reads the newest finished file for the take, else the newest raw take; the block's first line says which (`the newest finished file`, `the newest raw take: no finished file yet`, `given with --take-file`). The block is appended to `run-notes.md`. A file is **finished** when its name carries `mix`, `cap`, `sokii`, `trim`, `tempo` (or an adopted desk's `final`/`captions`), else **raw**.

## Finish

A raw take is never a deliverable. With the default `api_captions: true`, the API may also return a finished episode with server **house** captions; the operator deliverable is still the file from **`finish`** on the raw take. With `api_captions: false` (or `--no-api-captions`), the take step stops after the raw clip and only local captions apply:

```bash
uv run fictora-produce finish --desk D [--episode N] [--take tK] [--take-file F] \
  [--sfx-adjust "door=-6" | "hum=drop" | "shot:3=+4"] [--music "change note"] \
  [--line-start S ...] [--line-end S ...] [--no-deboard] [--no-colour-match] [--colour-strength 0..1] [--watermark-y Y] [--json] \
  [--mute A-B ...] [--voice FILE@S[@DB] ...] [--cue FILE@S[@DB] ...] [--caption-label TEXT@A-B ... | --no-caption-labels] [--sign-overlay] [--prop-text "@SHOT" --prop-box X,Y,W,H ...] [--caption-style bold|subtle|plain|none] [--no-cover] \
```

**System panels** (user decisions, 6 Oct 2026). The server places and draws them (fictora-drama `system-panels` route, free); the kit (`creation/post/system_panels.py`) only sends the takes' filmed lengths, burns the layer it gets back, and keeps no copy of the rules. A server without the route stops `finish` on a system or game show with "this Drama API cannot draw system panels yet; finish with --no-panels until it is updated"; other shows never ask. Only a show whose `microdrama_genre` or an overlay is `system_leveling`, `last_human`, `isekai`, `cultivation` or `regression_revenge` has them. The writer puts them on beats (`beats[].system_panels`: `form` status_window / quest_log / stat_sheet / alert / skill_unlock / level_up / realm_breakthrough / rank_change / dungeon_gate / system_message, 1-5 short `lines`, `numbers`, optional `style` {`frame` glass / hologram / neon / ink_scroll / parchment / brush, `palette` 1-3 `#RRGGBB`}, `anchor` beat / take, `appear_at_ms`, `duration_ms` 1.2-3 s, `position` upper / center / lower / upper_left / upper_right); the show's look is `system_panel_look`. Never pick or rewrite a panel for the creator: it is the writer's craft call. `finish` burns the take's panels after the captions and before the hook line: placed at the beat's even share of its take plus `appear_at_ms` (lengths of earlier takes from their raw files), at most two in a take, never the same form twice in a row, never two at once; drawn as an ASS layer (form decides layout, frame decides shape, palette from the look) with a typewriter reveal, inside the picture (the 4:3 picture on a letterbox canvas), under the top strip and the mark, above the caption band, out of the right rail, digits in Arial. The run notes list each panel (`System panels -> ...`). `--no-panels` draws none. Generated frames never carry panel text. A hosted episode carries them wherever its captions are burned.

**Hook line and title bar** (founder decisions, 5 Oct 2026; `creation/post/hook_overlay.py`). Every episode's outline carries three on-screen hook lines; the creator's pick (on by default) is `episode_summaries[].hook_line_selected.text`. `finish` burns it on the episode's first take (`t1`): large white bold, heavy outline, just under the top 8% strip, out of the right-hand rail, at most two lines, for the first ~3 s (it leaves on the first cut between 2.5 and 4 s, else fades at 3 s). It moves just above the captions when a face sits in the upper band (once the face helper can say where a face is; until then it stays on top), unless a caption is on screen while it is up: then it stays on top, so it never sits on the first caption, and the caption keeps its timing (founder, 7 Oct 2026, L-20261005-11; `finish` checks the captions it just burned). It is skipped, with the reason printed, when it says the same words as the first spoken line, or when it is off. `--hook-line TEXT` saves your own line on the server and burns the server's answer, `--no-hook-line` turns it off on the server, `--hook-line-position` forces the place. A show whose `delivery_format` is `letterbox` but whose takes were filmed portrait gets a solid title bar instead (series title + hook line, or the episode's `title_line`) across the top for the whole take, captions untouched. A take that is really 4:3 is finished into the 9:16 letterbox file (below). With no hook line on a portrait show nothing changes. **Choosing the hook line:** `hook-line --desk D --episode N --list` prints the writer's options from the saved spine (free, no call); `--pick K`, `--text "..."` or `--off` stores the choice on the server on the route the app's opening picker uses (`PATCH /v1/spines/{id}/episodes/{episode_id}/opening`, `hook_line: {kind: option, index} | {kind: custom, text} | {kind: off}`, free; a stale spine version is read again and sent once more). The server checks the line (seven words or fewer, no question to the viewer, not the first spoken line) and its notes print word for word. `finish` and `join` with `--hook-line TEXT` or `--no-hook-line` save the choice on the server the same way first, then burn the line the server answers (decision D1, 21 Oct 2026). An older server (a bare 404 or 405, or one that will not take your own words) stops the command: the kit keeps no copy on the desk any more. A pick an older run left in `shared/hook-line.json` is still read until the server holds one. **Setup line** (letterbox): `--setup-line "..."` (1-60 characters, checked before sending) sends `title_line: {kind: custom, text}` on the same route, as its own send after any hook-line choice; `--default-setup-line` sends `{kind: default}` (the series title). A server without the field (a 422, no route, or an answer without `title_line`) stops the command; the kit no longer keeps it on the desk (a line an older run left in `shared/setup-line.json` is still read). **Openings:** every episode outlined since 5 Oct 2026 has its own `opening_image` and `first_line` (or a silent opening), chosen by the creator from the writer's options; `preflight` prints it for a new episode.

- **Times** are seconds on the take as filmed (the raw take), for all three flags. `deboard` replaces the board frames without cutting, so nothing moves; never subtract the board frames. The server now does the same when it stores a Turbo take (take facts `board_frames`; `deboard` then finds 0). A take stored on 1 Oct 2026 while the server cut them (fictora-drama #543) is shorter than filmed: `finish` measures it against its dialogue track and writes the next take-facts version with every time moved (`take_facts_shifted_s`); a native take from then gets a `!!` instead. Place cues on the take, never on a joined episode.
- **`--caption-label TEXT@A-B`**: a caption with no spoken line under it (a one-word line the take never says clearly), A-B seconds on the take as filmed (repeat). Saved on the server first as the take's labels (`PUT /v1/spines/{id}/episodes/{episode_id}/caption-labels`, decision D2): the server draws each (no dash), checks it with the line rules (ten words, never said to the viewer; its notes print as `[caption-label] note: …`) and keeps it, and every `finish` of the take burns the labels the server holds. `--no-caption-labels` clears them. Nothing is laid in the sound. An older server stops the finish.

The sound line then ends `· hand voice ✗` or `· hand cues ✗`.
- No loudness normalisation on the take; the mix gives it one gain and one limiter.

Placing a cue:

- A cue answers something the viewer can see (a pour, a door, a cup set down). No picture, no cue. One cue per action: two read as two actions, and a looped cue under one gesture reads as the gesture repeating. Room tone and weather are the bed, not a cue per shot.
- Place it on the frame where the action lands, not where it starts: find it on the contact sheet, check it at full rate.
- Read its shape before placing it: an event must hit in its first half second and stay under about 3 s; a sustained sound must not die after its first half second, and on desks from 6 Oct 2026 must hold: after its first second, no one-second stretch more than 9 dB under the cue's median (`sustained sound fades`, re-rendered like any wrong shape; legacy desks keep the half-tail check). Trust the numbers, not the name. A cue wrong once is rendered once more (new words), then dropped with a line in the run notes. A missing cue never blocks the take.
- Level: start at the default −8 dB and move in 2–3 dB steps; a generated cue can come back quiet and need +10 to +20. A level note is a mix note, never a re-render. Write one line per hand cue in `run-notes.md` saying which action it answers.

`caption --desk D [--line-start S ...] [--line-end S ...] [--words-json J]` still burns captions alone (on any show it times lines on `--words-json`, default the newest saved `take-epNN-t1-*words-vN.json` when captioning the raw take; it never makes a transcript itself) on a raw take (timing detail: [local-captions.md](../../../docs/content-ops/local-captions.md)). Needs ffmpeg + ffprobe with libass. Generated audio (effects, the bed, audition clips, dry lines, Whisper timings) is made on the server by the Drama API operator audio routes (`sfx-cues`, `audio-bed/render`, `voice-auditions/render`, `voice-lines`, `/v1/transcripts`); no provider key ever goes on this laptop and no local file is uploaded (transcripts read the take's stored URL). Rate limits and in-progress answers are waited out automatically. If a route refuses (`operator_audio_unavailable`, `budget_cap_exceeded`), `finish` still does the look, mix, captions and mark, reports `NOT DONE` and names the refusal: tell engineering, never add a key. Costs go to `run-notes.md` only; never quote them to anyone else.

**Hosted post is off.** Never call `POST /v1/video-generations/{id}/post-production-runs`. ## Join

`fictora-produce join --desk D (--episode N | --episodes N M … | --take-file F …) [--dissolve S] [--gain-match | --no-gain-match] [--watermark-y N] [--hook-line TEXT | --no-hook-line] [--caption-colour yellow|white] [--no-cover] [--json]`. Free (ffmpeg + numpy); lays no music.

| Step | What it does | Thresholds |
| --- | --- | --- |
| Parts | `--episode`: the newest complete `take-epNN-tK-finish-vN.json` of every take (the desk's take list plus any recorded take), in take order. `--episodes`: that per episode, in the order given. `--take-file`: the record that names the file (the `-sokii` final, its un-marked `-cap` master, or the pre-bed take). | a desk take with no complete record (named with what its newest finish lacks), or a file no record names → refused |
| Checks | Before anything is written: every picture 24 fps, one size; the take before the mix as long as its picture. | 24 ± 0.2 fps; one frame + 0.05 s |
| Sound | Each take's sound before the mix (what the mix read: voice, SFX, hand cues) is cut or padded to its picture, gained to the takes' median integrated loudness, and joined on the samples. Gain matching is skipped by default when every take finished within ±0.5 LU of −18 LUFS (each record's finished file, measured; the join prints `gain matching skipped: …` and the note goes in the run notes): they already match, and matching them again only moves a quiet tail against a spoken open (Three Payments Late: a seam widened from 5.0 to 7.4 dB). `--gain-match` forces it; `--no-gain-match` keeps each take's level always. | silent takes gain 0; skipped when all finished at −18 ± 0.5 LUFS |
| Picture | The un-marked captioned masters; a cut between takes of one episode, a `xfade` dissolve (and a linear sound crossfade) between episodes. `--dissolve` sets every seam. | cut; 0.25 s between episodes |
| Music | None (founder decision, 20 Oct 2026): the joined sound gets the `finish` mix (measured gain to about −18 LUFS, one limiter) with no bed under it. A take an older finish left with music in its own sound (`music_in_take`) is named with a `!!` line, never refused | — |
| Measure | Counted frames / video seconds of the joined file. Room-level step across each seam: median of 0.1 s RMS windows over 2 s either side. | 24 ± 0.2; step > 5 dB → `NOT DONE`, exit 5, nothing marked |
| Mark | The Sokii mark once, on the joined master. A letterbox show (every part's record says `letterbox`): the mark in the top band and the title block above the picture, once, on the joined 9:16 file (`--hook-line` / `--no-hook-line`; a series cut uses its first episode's title block); the opening and tail checks read the picture only. Letterbox and other takes mixed: refused. | as `finish` |
| Cover | One episode (`--episode`, or one episode's takes): the marked episode is uploaded (`POST /v1/uploads` and the signed PUT), the server makes its free cover (`GET …/episodes/N/cover?video_url=<the upload>`) and it is saved as `cover-epNN-vN.jpg` next to the marked file (in `--json` as `cover`). Same rules as finish's cover step: no double upload, the same cover reused, a new one versioned, a failure is one plain line and the join still counts. A series cut gets none. `--no-cover` skips it | — |

Captions are the ones `finish` burned on each take (timed on that take's voice before the mix); they move with their picture, so they sit right on the joined timeline, and a caption inside a dissolve fades with it. A take edited after finish (`trim`, `tempo`, `freeze`, `soften`, `blur` on a file a finish record names) gets a new record: the same edit on the take before the bed and the un-marked master (`take-epNN-tK-<step>-{prebed,master,final}-vN.mp4`; `freeze`/`soften`/`blur` keep the pre-bed take, the sound is unchanged), the edit chain in `edits`. `join` reads it like any finish record, and the seam check follows the take's words through the edits (the handles, `trim`, `tempo`), so speech is still left out of the seam level after a trim or speed change. In a series cut, where two episodes meet, the last 4 s of the one and the first 4 s of the next are levelled toward each other (each half the step, at most 10 dB together; the run notes say `episode seam ... levelled`); the rest of each episode keeps its level, and a step the levelling cannot close still stops the join. A file no record names is refused (joining the marked finals by hand would stitch each take's bed and mark twice).

On a letterbox join the captions are the ones each take was finished with: `--caption-colour` that differs from them is refused with the `finish --caption-colour` to run on each take. `--hook-line`, `--no-hook-line` and `--caption-colour` on a portrait join are refused (its hook line is the first take's, burned at `finish`).

Outputs, never overwritten: `epNN/takes/episode-epNN-join-vN.mp4` (un-marked master, a working file) and the marked episode under its readable name `<show>_epNN_draft_vN_<YYYY-MM-DD>.mp4` (show = the title lowercased and hyphenated, at most 40 characters; `vN` is one count per episode across draft and final and carries on from an older desk's `episode-epNN-join-sokii-vN.mp4` files, which keep their names). `fictora-ops approve --desk D --gate post --episode N [--path FILE]` (the human says the episode is final) copies that file, default the newest, to `<show>_epNN_final_vN_<date>.mp4`, the next version; the draft stays; a cut across episodes goes to `shared/cuts/series-epNN-epMM-join[-sokii]-vN.mp4`. The report and a run note in every episode joined list the parts and their gains, the bed, each seam (cut or dissolve, step in dB), frames / seconds and loudness.

## Change a character's voice

The voice is a lock on the cast card, not part of the story or the picture. Never re-draft the story or re-film every take to change it.

**Voices gate.** It applies only to a show whose voice mode is `locked` (`voice-mode --desk D`; SKILL "Show voices"). On a `model` show (the video model's own voices from the cast descriptions) `step`, `voice --list`, the estimate and `film` print `Voices gate skipped` and nothing is held. The server locks a voice per character at draft time and locked takes film in it, so the human hears and approves each voice before the first take. After the script's yes (one step at a time: Script, then Voices, then Storyboard; founder phone test 22 Oct 2026) the kit prints Sokii's line for the step from the server (`GET /v1/spines/{id}/voices-step`, fictora-drama #990), every speaking character's voice and the commands, Keep all voices first; the estimate prints `!! A yes is for the voice it was given on: a voice changed afterwards (a new pick, a new cast card, a server recast) needs a new one. A job already in flight is never held. **The yeses live on the server** (`spine.voice_approvals`, fictora-drama #603), the same ones the creator app reads and writes: a voice the creator kept or picked in the app counts here, and a keep here counts there. `shared/voices/approvals.json` is now a mirror and a fallback. A yes recorded there only (a desk from before this change, or a keep while the server was older or unreachable) is pushed to the server once, the next time the gate reads it, and only while the card still locks the voice it was given for. A desk that had filmed a take before this gate (no `approvals.json` yet) is grandfathered: written once into `approvals.json` (`"grandfathered": true`), never held, and the gate text says so. After a voice change on any desk, `revoice` the takes already filmed that the character speaks in.

## Episode 2 on

Episode 1 is made on its own; the arc is chosen at episode 2, after episode 1 is approved. Ask the human how many episodes the run should be, then:

- Offer arcs sized to that run. For a long run prefer an engine (a situation that repeats with a new problem) plus a slow question; refuse an arc that closes within a few episodes.
- Each later episode is steered by its **direction**: the human picks one or says their own, and it goes to the writer in their words. Confirm the idea is in the printed script. Series-wide notes are for standing rules ("keep every episode punchy"), never for this episode's idea.
- Approve each episode's script on its own. Never pre-stage scripts for later episodes.

```bash
uv run fictora-produce arc --desk D --list [--episodes N]          # the three arcs, sized to the run (episode 2 only)
uv run fictora-produce arc --desk D --pick K [--title T] [--line L] [--episodes N]   # keeps it; prints episode 2's directions
uv run fictora-produce brief --desk D --episode N [--episodes N]   # directions for episode 3 on
uv run fictora-produce brief --desk D (--edit @FILE | --strip-narration) [--preview]   # replace the story's stored brief; shows the change first
uv run fictora-produce language --desk D --spoken ja|ko|en [--preview] [--confirm-filmed] [--confirm-episode-one-remake]   # change the show's spoken language; shows what it sets aside first
uv run fictora-produce author --desk D --episode N (--direction K | --line "the human's words" [--title T])
uv run fictora-produce rewrite --desk D --episode N --line "what to change, in the human's words" [--title T]   # a drafted, unapproved episode; free
uv run fictora-produce approve --desk D --gate script              # then step (boards), approve board, step (estimate), step --confirm-spend
uv run fictora-produce memory --desk D (--note TEXT | --thread TEXT)   # standing rules only
```

`--line` is counted before anything is sent: the server takes at most 400 characters (`DramaPilotEpisodeDirection.line`); a longer line is checked against the deploy's own `/openapi.json` limit (a server that raised it takes the longer line) and refused with the count when it is over, with no desk slot opened. `author` opens the desk slot, prints the script, and points the phase machine at the new episode.

`author` will not write a drafted episode again (`409 prior_episode_not_approved` / `invalid_extension_ordinal`). `rewrite` re-writes a drafted episode that is not approved yet (2 on; episode 1 and an approved episode are refused before anything is sent, naming `edit` / `line` or `author`). It adds `--line` (prefixed `T: ` with `--title`; the same limit as `author --line`, counted first) as an episode note (`POST /v1/spines/{id}/episodes/{episode_id}/notes`), removing the note the last `rewrite` of that episode added (recorded as `rewrite_notes` in `production.json`; the human's other notes stay and a later note wins where they conflict), then `POST …/pilot-episodes/{n}/rewrite` and polls its `rewrite_job_id` with a recorded idempotency key (`rewrite-epNN-aK`; an interrupted run picks up the same job and adds no second note). It spends nothing (a draft, booked nowhere), refreshes `api/spine.json`, syncs the lines, and prints the episode exactly as `author` does, ending with the same "Next: … say yes (`approve --gate script`) or edit them" line. The shared-spine guard applies (`--shared-spine-ok`). The season target is a soft default: an episode past it is written as "the season continues"; 240 is the only stop. The boards `step` sends `episode_count: N` and the server draws only the episodes up to N that still lack boards, so episode N is drawn and booked alone. The take films with `episode_count: N, episode_ordinal: N`: episode N alone (episodes 1..N must be approved; none of them is filmed or booked again), and its first take opens on the previous episode's stored last frame when the location matches (nothing to paste by hand).

Episode ids: the server names every new episode `episode_NN`; a story made before 2026-09-28 keeps `ep_02` and on for its later episodes. The kit finds episodes by ordinal, and the spine routes (notes, dialogue) accept either form.

## Film one episode, or one take of it

```bash
uv run fictora-produce film --desk D --episode N --take tK --cause "what in the direction made the fault"   # prices take K alone; spends nothing
uv run fictora-produce film --desk D --episode N --take tK --cause "…" --confirm-spend                     # after the human's yes: films only take K
uv run fictora-produce film --desk D --episode N [--cause "…"] [--confirm-spend]                          # the whole episode N, alone
```

- Without `--confirm-spend` it prices exactly what will be filmed (`batches/estimate` with `reroll_take_index` for one take) against the envelope and stops. `--confirm-spend` refuses until that number was shown.
- It sends `POST /v1/video-generations` with `episode_count: N, episode_ordinal: N`, plus `reroll_take_index: K, seed_attempt: <films so far + 1>` for one take. The new take lands as the next `take-epNN-tK-raw-vN.mp4` with its take facts; only it is booked. The other takes stay as filmed.
- A take (or episode) already filmed needs `--cause` naming what in the direction produced the fault; "try again" is refused. The cause is recorded on the take as Change this and in `run-notes.md`.
- Only from a board with a human yes on the desk. An interrupted `film` (a timeout, a broken poll) run again picks up its job and never pays twice. A job the server ended `failed` or `cancelled` is cleared: nothing is collected or booked, and the next `film --confirm-spend` (after the human's yes) enrols a new job under a fresh key instead of re-reporting the old failure. Each poll reads both `/v1/jobs/{id}` and `/v1/video-generations/{id}` and stops on the first that says `failed` or `cancelled`, with the server's code and message (`… (reported by /v1/video-generations/{id}; /v1/jobs still said running 0%)`): the job route can keep saying `running 0%` long after the video generation failed. When the job's status, progress, take jobs and clips have not moved for 10 minutes, the film poll prints `WARNING: video job job_video_…: The server has not updated this job for N min …` with the `status` and `cancel-job` commands (again every 10 minutes); it never retries or films again by itself.
- An older deploy without `episode_ordinal` is refused before anything is sent (episode 1 films alone either way). Say so to the human and tell engineering.
- **Shot clips were removed (founder, 19 Oct 2026: "feels like a trailer").** There is no `shot-clips` command and no `film --shot-clips` / `--clip` any more; every show films whole takes. Iron Saint ep 2 "Low Tide", filmed as shot clips on 16-17 Oct, keeps its takes as filmed: it plays, finishes, joins and shares like any episode. Fight takes now play as one continuous camera shot with a wind-up, one clear hit and the follow-through.
- **Single-picture opening is OFF by default again (since 9 Oct 2026, fictora-drama #694).** A film with no flag opens each take on the storyboard, as before 8 Oct, for every show (new stories and continuing series, kit and app alike): the 8 Oct default (option B, #678) changed continuing shows' art style (Mihir, 9 Oct), so the server rolled it back. `--single-frame-start` (`film --episode N … --confirm-spend --single-frame-start`, or `step --confirm-spend --single-frame-start`) turns the single-picture opening on for that one film, for tests only (take 1 on its board's first cell filled to the frame, later takes on the previous take's last frame; fictora-drama #658, shot text #665/#673/#675; price unchanged); it prints `Opening each take on a single full picture instead of the storyboard`. Never use it on a show's real episodes without the founder's yes. `--no-single-frame-start` is still accepted and sends the storyboard opening explicitly (the same as no flag today); it prints `Opening each take on the storyboard (--no-single-frame-start)`. The two flags cannot go together. Either choice is kept on the film (`pending` for `film`; `single_frame_start_keys` / `single_frame_start_off_keys` in `production.json` for `step`), so a resumed run sends the same request without the flag; a film already sent one way is never resent another way under its key. A server that will not take the choice (not an operator account) stops with "The opening choice … isn't available for this show or account", nothing filmed or charged; film again without the flag. The take-leak trim (`board_leak_trim`) stays on as the safety net for the storyboard flash.
- **`--reference-mode` is removed** (founder, 8 Oct 2026: double the take cost was rejected). Takes film on the server's standing lane; there is no per-take reference-lane option. A desk holding a film first sent with it and never admitted stops with "This film was first sent with --reference-mode, which was removed …", nothing sent or charged: ask engineering whether the first send was admitted before filming that take again. A film the server already admitted is picked up and collected as usual.

## API contract

| Item | Value |
| --- | --- |
| Base URL | `FICTORA_DRAMA_GENERATION_API_BASE_URL` (see `.env.example`) |
| Auth | `Authorization: Bearer`, `X-Drama-Session-Id` on every `/v1` call |
| Mutations | `Idempotency-Key` required |
| OpenAPI | `{base}/openapi.json`, `{base}/docs` |

Sequence `fictora-produce` runs: `POST /v1/prompt-video-authoring-drafts` (`episode_count: 1`, `outline_mode: arc_at_episode_two`, `cut_tempo`) → cast enrol → cast approve → spine approve → boards enrol + exposure → boards approve → `batches/estimate` (this episode) → `POST /v1/video-generations` → raw takes from the take jobs + `GET /v1/jobs/{take}/take-facts?spine_id=`. Episode 2 on: `director/brief` → `series-arc` → `pilot-episodes/{n}/author` → `pilot-episodes/{n}/approve` → boards (`episode_count: N`) → estimate → take (`episode_count: N, episode_ordinal: N`). One take: `batches/estimate` with `reroll_take_index: K`, then the take with `reroll_take_index: K, seed_attempt`. `/delivery` is never needed (hosted post is off). Presets: `GET /v1/art-style-presets` (`fictora-produce presets` prints it; `start`/`bind` refuse an id that is not there, or a tenant preset not yet `published`, and list the valid ids).

- `edit --set KEY=VALUE`: dotted keys, and a number steps into a list (`--set 'subject_blocking.0.pose=arms crossed'`, `--set 'story_objects.1=a lacquer tray'`). A value starting with `"`, `[` or `{`, or `null`/`true`/`false`, is JSON: `--set 'shot_scale="extreme close-up"'` stores `extreme close-up`, not the quotes. Anything else is the text as typed (`--set shot_scale=extreme close-up` works too); numbers stay text. The printed change names the field inside the list (`visual_brief.subject_blocking.0.pose`).
- A frame's `--set` always sends the WHOLE current `visual_brief` with only the set fields changed (the server replaces the brief with what is sent). Who is in the shot: `--set 'subject_blocking=[…]'` (one entry per person) also sends `cast_refs` as the blocking's ids when the people change; `--set 'cast_refs=["Hana"]'` (names or ids) sends `cast_refs` alone, no brief, and the server keeps the staging of whoever stays (fictora-drama #498; an older deploy refuses it: edit the blocking). When it adds someone already in the episode (a line in it, or in one of its shots; anyone else is refused before sending: give them a line in the episode first), the kit sends the whole brief with a default `subject_blocking` entry for them (`creation/default_staging.py`: their side on the episode's nearest other frame, else opposite the first person staged, centre when alone; still pose; facing that person) and prints it, so the server's `frame_cast_needs_staging` is not hit. Both naming different people is refused before sending.
- A refused beat or frame edit: from fictora-drama #498 the server names the field and rule (`details.validation_errors`, a message naming fields) or the frame-cast rule (`frame_cast_needs_staging`, `frame_cast_mismatch`, `off_screen_cast_on_frame`, `voice_only_cast_on_screen`, `details.unknown_frame_cast_ids`); the kit prints those rows and the fix. On an older deploy the refusal is a bare `invalid_patch` ("The story spine patch is invalid." / "The cascade preview edit is invalid.", no field detail) and is explained under the message: what the request carried, the fields this edit changed, and which of them are strict. An enum field set to a value the deploy's `/openapi.json` does not list is named with the values it takes (`cell_role` is one of anchor, reaction, action, insert, cover); `reaction_kind` is a kind from `GET /v1/capabilities` (on a beat, `--expression`); `reaction_cast_id` needs a `reaction_kind` and a cast id in that frame's `subject_blocking`; list fields need at least one item, none blank.
- `edit` before the script gate is a plain patch. After it, the server asks for a cascade: `edit` prints every item, runs the free ones, and leaves the paid ones (`tier media`) off unless `--select-regen`; it names each board that no longer matches (redraw it with `redraw-board`). `--preview` stops after the list.
- `edit --beat N --shot …` (repeat 1–4 times), `--shot-plan '[{"size": "close-up", "subject": "Hana's face", "camera": "slow dolly in", "angle": "high angle"}]'` (or `@FILE`; the list, or an object holding it under `shot_plan`) or `--clear-shot-plan` sets the beat's `shot_plan` (`PATCH` before the script gate, the cascade after it; the cascade marks the take's frames and names the board to `redraw-board`). The kit checks the plan first (1–4 shots, `size` and `subject` required, one line of at most 200 characters each) and prints the plan the server now holds. It needs fictora-drama #464 on the server: an older server refuses the field (`422`) and `edit` says so; if an older server answers but drops it, `edit` prints `!!`. A plan longer than the beat's board rows is clamped on the server (logged), never refused.
- `edit --beat N --expression KIND|none` sets the beat's `reaction_kind` (`null` for `none`), alone or with `--intent`/`--set`/a shot plan in the same beat patch. Before anything is sent it reads `/openapi.json` (a deploy whose `DramaBeatPatch` has no `reaction_kind` is refused as older than fictora-drama #482) and `GET /v1/capabilities` (404 is refused the same way), and checks the kind or label against the deploy's list; an unknown kind stops with the list. It prints the expression the server now holds, and `!!` if the server answered but dropped it. After the script gate it goes through the cascade like any beat edit.
- `line` changes one line on the server (`PATCH /v1/spines/{id}` `dialogue_lines`, or the cascade after the script gate), saves `api/spine.json` again and puts the server's lines on the desk in the same step. It prints what happened to the script approval: before the gate, the line is part of what the human approves; after it, the server keeps the script approved, but the desk's script yes was for the old line, so it is pending again and preflight will not film until `fictora-ops approve --desk D --gate script --episode N` after the human's yes. `--speaker` takes someone already in the cast; `--off-screen` marks a speaker heard, not seen. It warns when the speaker is not drawn in the frame the line plays on.
- `line --add --beat N --speaker NAME --text "..." [--off-screen]` gives a beat a line (`add_dialogue_lines`, with the pacing `tier` the server would give its length: up to 2 words `micro`, up to 6 words in one sentence `standard`, else `extended`; a line stored without one stops the next episode's author); `line --remove ID` drops one (`remove_dialogue_line_ids`; its voice clip goes with it). A beat holds one line, so to replace a line send both in one command: `--add --beat N ... --remove OLD`. A new character who is only heard (an intercom, a caller) comes with its line: `line --add --beat N --text "..." --new-voice NAME --role "..." --voice-description "how it sounds" [--provider-voice X]` (`add_voice_only_cast`; cast id `cast_<name>`; the line is always off screen, and the voice gets no plate). The server refuses by name and `line` prints the fix: `beat_already_has_line` (remove the old line in the same command), `line_speaker_not_motion_subject` (the beat's shot moves someone else: re-run with `--speaker-moves` to make the speaker the motion subject, or pick a beat where the speaker moves), `voice_only_cast_on_screen`, `voice_only_cast_needs_a_line` (send `--new-voice` with `--add`), `cast_id_taken`, `cast_limit_reached` (a series holds 50 named characters; background people never count: give the line to someone in the cast), `line_id_taken` (`spine --refresh`, try again), `invalid_patch` (the fix is the rule the server names, e.g. `reaction_cast_id needs a reaction_kind`; an id not on the story only when the server names an unknown id, or as one possible cause on a deploy older than fictora-drama #498 that names nothing), `cascade_edit_out_of_scope` (after the gate, one episode per command). Word counts are advisory. Without `--provider-voice` the server picks the voice: a current server (fictora-drama ec6fec0e) the Eleven v3 voice that best fits `--voice-description` (the gender it names is a filter, then accent, age and timbre); an older deploy the first voice nobody in the cast uses, whatever the description says (a "hoarse adult man" came back a woman's voice). `line` prints the voice the server picked either way. Hear it before filming: `voice --desk D --cast cast_<name> --audition --voices A,B,C,D` (four voices that fit), then `voice --pick N`; or pass `--provider-voice` up front. After the script gate it goes through the cascade like any line edit (the preview lists the beat's clip, the take's board and the re-cut; paid items off unless `--select-regen`), and the desk's script yes goes back to pending. It needs fictora-drama #466 on the server (now carried by #469); an older server refuses the new fields (`422`), and `line` prints that refusal.
- `line --add --new-voice … --look TEXT|@FILE` also gives the new voice a look once it is added (the look is checked first; if it is refused the voice stays and the stop prints the `cast` command that sends it). For someone heard now who may be drawn later.
- `cast --desk D --name NAME --look TEXT|@FILE` gives one cast member a look: `visual_description` and a `visual_brief` in the cast brief shape (`age_band`, `face_anchors`, `hair_anchors`, `gender_presentation`, `silhouette`, `wardrobe_anchors`, `default_expression`/`gaze`/`posture`, `visual_medium`, `surface_treatment`, `palette`, `reference_lighting`, `reference_background`, `forbidden_elements`). The look is `key: value` lines (age, gender, face, hair, silhouette, wardrobe, expression, gaze, posture, palette, never, medium, surface, lighting, background; list fields split on `;`; any other line is the description, else one is written from the anchors) or a JSON brief. A card with a brief is edited (only the fields given change; with no description in the look the card keeps its own, its stated age moved to a new `age:`, so `age: 28` alone never drops the ethnicity or hair); a card with none starts from the show's drawing style (another cast card's medium, surface, palette, lighting and background) with expression, gaze and posture defaulted (`neutral, composed`, `steady, toward the viewer`, `relaxed, upright`). A missing anchor stops before anything is sent. It prints the change, then sends `PATCH /v1/spines/{id}` with `cast[]` before the script gate, or the cast cascade after it (`cascade/preview` with `{scope: field, target_type: cast_card, target_id, patch}`, then `execute`; paid items off unless `--select-regen`). `--preview` sends nothing before the gate and only previews the cascade after it. Then it prints the next step: `redraw-plate --cast NAME --note "first drawing from the new look"` for a drawn character with plates, the plates step before any plate exists, or that a character only heard gets no plate yet. Like `edit` and `line`, `cast` and `line --new-character` end on `Applied` / `Refused: <reason>` / `Not applied` (a stopped `--new-character` names the edits not made).
- `cast-exit --desk D --cast NAME --after-episode N` marks a character as gone after episode N (they died, left, their arc ended): it sets the card's `exit_episode_ordinal`, through `PATCH /v1/spines/{id}` with `cast: [{cast_id, exit_episode_ordinal: N}]` before the script gate, or the cast cascade after it (`target_type: cast_card`; paid items always off). From episode N+1 the writers see one line for them ("gone after episode N") instead of their whole card. `--clear` sends `exit_episode_ordinal: null` and brings them back. NAME is a name or a cast id; an unknown name, or a name two characters share (pass the cast id), stops with nothing sent, and so does an episode before the one they first appear in (the server's rule: nobody leaves before they arrive; leaving in their first episode is fine). It prints `NAME is marked as leaving after episode N. Writers will see one line for them from episode N+1; run with --clear to bring them back.`, and a note when the stored story still gives them lines after N. Nothing is redrawn or re-voiced, and nothing is charged. Limits behind it: a series holds up to 50 named characters (background people never count), a shot at most 4 people, a take at most 8 named people and at most 6 speakers on H3 Turbo or 3 on H3 Max and Seedance.
- `outfit --desk D --cast NAME` calls the server's outfit plan (fictora-drama): `POST /v1/spines/{id}/outfits` with `{spine_version, cast_id, add?: {label, instruction}, wear?: {wardrobe_variant: LABEL|null, episode_ordinals}, remove?: LABEL, preview}` and `GET /v1/spines/{id}/outfits`. The server keeps the outfits on the card (`visual_brief.wardrobe_variants`, at most 4, labels unique in any case), the plan (`outfit_plan` on the story: who wears which outfit in which episodes) and the tags on written shots (`subject_blocking[].wardrobe_variant`, null = base); when it writes an episode later it puts the planned outfit on that person's shots. With no action `outfit` lists (GET) the base outfit, each named outfit with its words, the plan, per written episode how many of their shots wear what, and planned episodes not written yet; it sends nothing. `--add LABEL --look TEXT|@FILE` adds the outfit (or rewords one the card has; the same words change nothing); `--wear LABEL|base --episodes 5|5-6|5,7` plans it and tags their written shots; `--add` and `--wear` together go in one request; `--remove LABEL` comes alone. `--preview` sends `preview: true` (the answer as the change would be, nothing stored). It prints per episode the shots changed (`tK frame: before -> after`, `epNN: K shot(s) now "LABEL".`), `epNN: shots not written yet; the writer will put "LABEL" on when they are written.` for `pending_episode_ordinals`, and for each of `boards_to_redraw` the `redraw-board --episode N --take tK --cause "outfit: LABEL"` that redraws it ($0.30, never run here). When the answer says `sheet_needs_redraw` and their sheet is drawn, it prints `NAME's sheet: one redraw so it shows "LABEL" next to the base outfit, about $0.30. Nothing drawn yet.` and `Human yes, then ... --add "LABEL" --confirm-spend`; that run redraws the plate (`redraw-plate`'s flow, booked on the ledger); `--confirm-spend` with no price shown prints the price and draws nothing. Refusals read plainly: `cast_not_drawn` (heard only: `cast --look` first), `unknown_wardrobe_variant` (names `--add`), `wardrobe_variant_limit` (4 a card), `outfit_in_use` (the episodes still wearing it); a `spine_version_conflict` is sent once more with the latest version. A 404 that is not `spine_not_found`/`cast_not_found`, or a 405, stops with "server too old" and edits nothing (no fallback to shot-by-shot edits). A desk with the first `outfit`'s `shared/outfits.json` sends its plan as `wear` requests on the next `outfit` run and renames the file `outfits.migrated.json` (it stays when the server is too old). A server picture-check finding of kind `wrong_outfit` prints with a line naming `outfit` and `redraw-board --same-shots`.
- `emotion --desk D` calls the server's emotion plan (fictora-drama, L-20261015-2): `--ask "TEXT"` (first choice, alone) sends `POST /v1/spines/{id}/emotions` `{spine_version, request_text: TEXT, preview: true}`; the server always answers a preview (HTTP 200) with `inferred_add` (a plan entry), or `inferred_default` with `cast_id`, or `refusal {code, message}` (`not_an_emotion_request`, `unknown_cast`, `ambiguous_cast`, `split_ranges`, `everyone_mood`). The kit prints the preview as for the flag forms (`Preview: …`, faces, lines, `redraw-board` lines at $0.30) or stops with the refusal's message. `--ask "TEXT" --confirm` asks again (nothing is kept between runs) and applies exactly what came back: `POST …/emotions {spine_version, add: inferred_add}` or `PUT …/cast/{cast_id}/emotional-default {spine_version, emotional_default: inferred_default}`, printing `Read as: …` first. A server that answers `request_text` with a 422, or with none of the three fields, stops with "cannot read a plain sentence yet" (use the flag forms). The flag forms: `GET /v1/spines/{id}/emotions` (`{spine_id, spine_version, series_plan, cast: [{cast_id, name, emotional_default, plan, episodes: [{episode_ordinal, mood, mood_source, no_tears, tear_shots}]}]}`), `POST /v1/spines/{id}/emotions` with `{spine_version, add?: {cast_id|null, from_episode, through_episode|null, mood|null, no_tears|null, note}, remove?: ENTRY_ID, preview}` (one of add/remove), and `PUT /v1/spines/{id}/cast/{cast_id}/emotional-default` with `{spine_version, emotional_default: {mood, note}|null, preview}`. Moods: neutral, angry, composed, shocked, happy, sad, deflated, flustered (the server checks them). ## Debugging (a declared deviation)

Only when `fictora-produce` cannot surface a failure: read-only `GET` of the spine or a job via `creation.harness.session.DramaApiRunSession` with the desk's `session_id`. No mutations, no prompt fetches. Engineering smoke (not production): `uv run python scripts/smoke_live.py --phase read`.
